## 1. Цель работы

Ознакомиться со средствами стандартного ввода-вывода и научиться использовать

## 2. Краткие теоретические сведения

**Стандартные потоки.** Ввод с клавиатуры и вывод на экран операционная система
представляет программе как чтение из файла и запись в файл. Для этого ОС сама,
до запуска программы, открывает три «воображаемых» файла: стандартный ввод
(stdin), стандартный вывод (stdout) и стандартный вывод ошибок (stderr). По
умолчанию ввод связан с клавиатурой, а вывод и ошибки — с экраном терминала
(учебное пособие, п. 2.2).

**Хэндл (дескриптор).** Для каждого открытого файла ОС создаёт управляющий блок
(file control block) и хранит его в своей служебной таблице отдельно для каждого
процесса. Хэндл — это просто номер строки в этой таблице; программа передаёт его
системным функциям, а ОС по номеру находит нужный блок (п. 2.1).

**Unix/Linux.** Номера стандартных потоков зарезервированы навсегда: 0 — ввод,
1 — вывод, 2 — ошибки. Их можно писать в программе константами и сразу
вызывать `read(0, ...)` и `write(1, ...)`.

**Windows.** Фиксированных номеров нет, их значения заранее неизвестны. Хэндлы
запрашивают функцией `GetStdHandle` с одной из констант `STD_INPUT_HANDLE`,
`STD_OUTPUT_HANDLE`, `STD_ERROR_HANDLE`; при неудаче она возвращает
`INVALID_HANDLE_VALUE`, поэтому результат проверяют. Затем хэндлы используют в
небуферизованных `ReadFile` и `WriteFile`.

**Переадресация.** Так как программа работает только с номерами стандартных
потоков, оболочка может перед запуском «подменить» то, на что они указывают:
`<файл` связывает ввод с файлом, `>файл` — вывод с файлом (прежнее содержимое
файла теряется, `>>` дописывает в конец), `2>файл` — поток ошибок. Сама
программа при этом не меняется.

**Различие консоли и файла.** В Linux функция `isatty(handle)` возвращает не ноль,
если хэндл связан с терминалом, и ноль, если с обычным файлом. Это позволяет
программе вести себя по-разному при вводе с клавиатуры и из файла.

## 3. Формулировка задания

**Базовый вариант.** Разработать в Windows программу, которая получает хэндлы
стандартного ввода и вывода, выводит их числовые значения с комментариями, затем,
используя небуферизованные функции `ReadFile`/`WriteFile`, делает приглашение для
ввода, вводит любой текст и выводит его с предуведомлением, что он предварительно
введён в программу. Предуведомление — отдельным оператором вызова функции
системного вывода. Продемонстрировать работу как со стандартным вводом-выводом
по умолчанию, так и с переназначением ввода на файл и вывода в файл.

**Усложнённый вариант.** Разработать аналогичную программу в Linux: приглашение
на ввод выводится только при вводе с консоли; при переадресации ввода на файл
приглашения быть не должно; при переадресации вывода в файл и вводе с консоли
приглашение должно принудительно появляться на экране, а не в файле. Значения
хэндлов не выводить.

## 4. Листинг программы (Windows, базовый вариант)

Файл `lab01/lab1.c`.

```c
/*
 * ЛР №1, базовый вариант (Windows).
 *
 * Программа получает хэндлы стандартного ввода и вывода, выводит их значения,
 * делает приглашение, вводит текст и выводит его с предуведомлением.
 * Используются только небуферизованные системные функции ReadFile/WriteFile.
 *
 * Сборка:  gcc lab01/lab1.c -o lab01/lab1.exe -Wall
 */
#include <windows.h>
#include <stdio.h>   /* sprintf — только для форматирования строки в памяти */
#include <string.h>

int main(void)
{
    /* Кодовая страница UTF-8 для консоли: чтобы русский текст исходника
     * (он хранится в UTF-8) отображался и вводился правильно. */
    SetConsoleOutputCP(CP_UTF8);
    SetConsoleCP(CP_UTF8);

    /* В Windows номера стандартных потоков заранее неизвестны — их нужно
     * запросить у ОС. Это и есть хэндлы стандартного ввода и вывода. */
    HANDLE hStdIn  = GetStdHandle(STD_INPUT_HANDLE);
    HANDLE hStdOut = GetStdHandle(STD_OUTPUT_HANDLE);

    /* Результат обязательно проверяем: при неудаче вернётся INVALID_HANDLE_VALUE. */
    if (hStdIn == INVALID_HANDLE_VALUE || hStdOut == INVALID_HANDLE_VALUE) {
        return 1;
    }

    char  msg[256];
    DWORD written = 0, readBytes = 0;   /* сколько байтов реально записано/прочитано */
    int   len;

    /* Числовые значения хэндлов с комментариями. Сначала формируем строку
     * в памяти (sprintf), затем выводим её системной функцией WriteFile. */
    len = sprintf(msg,
        "Handle stdin  = %p\r\nHandle stdout = %p\r\n\r\n",
        hStdIn, hStdOut);
    WriteFile(hStdOut, msg, (DWORD)len, &written, NULL);

    /* Приглашение на ввод. Выводится безусловно в stdout — поэтому при
     * переадресации вывода в файл оно тоже окажется в файле. */
    const char *prompt = "Введите произвольный текст: ";
    WriteFile(hStdOut, prompt, (DWORD)strlen(prompt), &written, NULL);

    /* Ввод текста. ReadFile возвращает управление, когда в консоли нажат Enter
     * (или когда прочитан файл, если ввод переадресован); в readBytes — число
     * реально прочитанных байтов. */
    char buf[256];
    ReadFile(hStdIn, buf, sizeof(buf) - 1, &readBytes, NULL);
    buf[readBytes] = '\0';

    /* Предуведомление — отдельным вызовом системной функции вывода. */
    const char *notice = "\r\nРанее введённый в программу текст:\r\n";
    WriteFile(hStdOut, notice, (DWORD)strlen(notice), &written, NULL);

    /* Сам введённый текст: выводим ровно столько байтов, сколько прочитали. */
    WriteFile(hStdOut, buf, readBytes, &written, NULL);

    return 0;
}
```

Сборка: `gcc lab01/lab1.c -o lab01/lab1.exe -Wall` (предупреждений нет).

## 5. Листинг программы (Linux, усложнённый вариант)

Файл `lab01/lab1_linux.c`.

```c
/*
 * ЛР №1, дополнительное задание (Linux / POSIX).
 *
 * Только системные вызовы read()/write()/open()/isatty() на дескрипторах —
 * без printf/scanf (у них свой буфер в пользовательском пространстве).
 *
 * Требования задания:
 *  - приглашение показывать, только если ввод идёт с консоли (stdin = терминал);
 *  - при "<input.txt" приглашения нет;
 *  - при ">out.txt" приглашение всё равно должно появиться на экране, а не в файле;
 *  - числа-дескрипторы не выводить.
 *
 * Сборка: gcc lab1_linux.c -o lab1_linux -Wall
 */
#include <fcntl.h>   /* open, O_WRONLY */
#include <string.h>  /* strlen */
#include <unistd.h>  /* read, write, close, isatty, STDIN_FILENO ... */

int main(void)
{
    char buf[256];

    /* Приглашение — только если дескриптор 0 это терминал.
     * isatty(0) != 0 -> ввод с клавиатуры; 0 -> stdin переадресован
     * на файл/канал ("<file", "|"), и приглашение не нужно. */
    if (isatty(STDIN_FILENO)) {
        const char *prompt = "Введите произвольный текст: ";

        /* Куда писать приглашение? НЕ в дескриптор 1: при "> out.txt"
         * он указывает на файл, и приглашение попало бы туда.
         *
         * Выбран /dev/tty — управляющий терминал процесса. Он не зависит
         * ни от одной переадресации, поэтому приглашение гарантированно
         * (принудительно) оказывается на экране.
         *
         * Альтернатива — stderr (дескриптор 2). Это стандартный приём
         * ("диагностика и подсказки не в stdout"), но он слабее: при
         * "2> err.txt" или "2>&1 > out.txt" приглашение снова уйдёт в файл.
         * stderr используем только как запасной вариант, если /dev/tty
         * открыть не удалось. */
        int out = open("/dev/tty", O_WRONLY);   /* открыть терминал на запись */
        if (out < 0)
            out = STDERR_FILENO;                /* запасной вариант */

        write(out, prompt, strlen(prompt));     /* вывести приглашение */

        if (out != STDERR_FILENO)
            close(out);                         /* свой дескриптор закрываем, чужой — нет */
    }

    /* Читаем из дескриптора 0 одним вызовом (для терминала — одну строку,
     * для файла — до sizeof(buf) байт). Возвращает число прочитанных байт,
     * 0 — конец файла, -1 — ошибка. */
    ssize_t n = read(STDIN_FILENO, buf, sizeof(buf));
    if (n < 0)
        return 1;

    /* Предуведомление — отдельным вызовом write() в stdout (дескриптор 1),
     * как в базовом варианте. Оно должно попасть в файл при ">out.txt". */
    const char *notice = "\nРанее введённый в программу текст:\n";
    write(STDOUT_FILENO, notice, strlen(notice));

    /* Выводим ровно столько байт, сколько прочитали. */
    write(STDOUT_FILENO, buf, (size_t)n);

    return 0;
}
```

Сборка: `gcc lab01/lab1_linux.c -o lab01/lab1_linux.out -Wall -Wextra`
(предупреждений нет).

## 7. Объяснение результатов

1. **Значения хэндлов в Windows** (6.1, 6.2) — не фиксированные числа, а номера
   записей в таблице хэндлов процесса. Они меняются от запуска к запуску и
   зависят от того, к чему подключены ввод и вывод: консоль или файл.
2. **В 6.2 приглашение оказалось в `output.txt`.** Базовая программа пишет и
   значения хэндлов, и приглашение, и результат одним и тем же вызовом
   `WriteFile(hStdOut, ...)`. Она не проверяет, на что указывает `hStdOut`; при
   `>output.txt` это файл, и туда попадает всё. Поэтому в файле остаётся и
   «Введите произвольный текст:». Вводимые данные при этом берутся из
   `input.txt`, а сама программа ничего не ждёт.
3. **В Linux приглашение зависит от `isatty(0)`.** При `<input.txt` стандартный
   ввод — файл, `isatty(0)` равен 0, приглашение не выводится (6.3, 6.4).
4. **Почему приглашение не попадает в `out.txt` (6.6).** Результат программа пишет
   в дескриптор 1, а приглашение — в `/dev/tty`, управляющий терминал процесса. Он
   не зависит от переадресации дескрипторов 0–2, поэтому приглашение
   гарантированно видно на экране. Запасной вариант — дескриптор 2 (`stderr`):
   он тоже не равен `stdout`, но слабее, так как при `2>файл` приглашение ушло бы
   в файл.
5. **Предуведомление** выводится отдельным вызовом `write`/`WriteFile` и поэтому,
   как и введённый текст, попадает в выходной файл (6.2, 6.4, 6.6).

## 8. Ответы на контрольные вопросы

**1. Где в ходе построения исходной программы, использующей стандартный
ввод-вывод, записываются файловые дескрипторы или хэндлы, в каких частях или
функциях?**
В Unix/Linux номера 0, 1, 2 фиксированы, поэтому их записывают прямо
константами (или `STDIN_FILENO`/`STDOUT_FILENO`) в первом аргументе вызовов
`read` и `write`. В Windows номера заранее неизвестны: в начале программы их
получают вызовами `GetStdHandle`, сохраняют в переменных типа `HANDLE`
(с проверкой на `INVALID_HANDLE_VALUE`) и затем подставляют первым аргументом в
`ReadFile` и `WriteFile`. Сами управляющие блоки файлов хранятся не в программе, а
в служебной таблице операционной системы; хэндл — номер строки этой таблицы.

**2. Зачем используется переадресация стандартного ввода-вывода?**
Чтобы одна и та же программа, без изменения исходного текста, могла получать
данные с клавиатуры или из файла и выдавать результат на экран или в файл. Это
позволяет автоматизировать запуск (пакетная обработка, тесты), сохранять
результаты работы и протоколы, отделять ошибки от обычного вывода (`2>`).

**3. Сколько существует разновидностей стандартного ввода-вывода?**
Три: стандартный ввод (stdin; дескриптор 0 или `STD_INPUT_HANDLE`), стандартный
вывод (stdout; 1 или `STD_OUTPUT_HANDLE`) и стандартный вывод ошибок (stderr; 2
или `STD_ERROR_HANDLE`).

**4. Чем отличается вызов исполняемой программы в командной строке Windows от
вызова программы с тем же именем в командной строке Linux?**
В Windows, находясь в каталоге программы, достаточно набрать её имя, причём
расширение можно указывать или опускать (`lab1.exe` или `lab1`). В Linux перед
именем программы необходимо явно указывать каталог; для текущего каталога —
`./имя`. Кроме того, в Linux программа, чтобы быть запущенной, должна иметь право
на выполнение (бит `x`).
