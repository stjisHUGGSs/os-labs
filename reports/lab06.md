## 1. Цель работы

Изучить средства использования множественных процессов в Windows: создание процессов,
передачу им информации, принудительное завершение и объединение процессов в
«задание» (Job).

## 2. Краткие теоретические сведения

**Создание процесса.** В Windows процесс порождается функцией `CreateProcess` с
десятью параметрами (учебное пособие, п. 7.2). Основные: имя программы или командная
строка (`pCommandLine`; первое слово — имя exe-файла, остальное — аргументы), флаги
создания (`CreateFlag`: класс приоритета, например `NORMAL_PRIORITY_CLASS`,
и другие, например `CREATE_SUSPENDED`), структура `STARTUPINFO` (в ней обязательно
заполняют только `cb` — размер) и `PROCESS_INFORMATION` для результата. После вызова
в этой структуре: `hProcess` и `hThread` — хэндлы процесса и его главной нити,
`dwProcessId` и `dwThreadId` — идентификаторы. Хэндлы после использования закрывают
`CloseHandle`. Передача данных новому процессу — через командную строку: программа
получает её в `argv`.

В Unix для этого служат `fork()` (раздвоение процесса) и семейство `exec…` (замена
программы процесса).

**Уничтожение процесса.** `TerminateProcess(hProcess, код)` принудительно завершает
*один* процесс; процессы-потомки при этом продолжают работать, пока не завершатся
сами (как в Unix после `kill(pid, SIGKILL)`).

**Задание (Job).** Начиная с Windows 2000, в Windows введён объект ядра *Job*,
собирающий произвольную группу процессов. Для группы можно задавать общие
ограничения, а главное — одним вызовом `TerminateJobObject(hJob, код)` уничтожить все
её процессы. Порядок работы (методические указания, ЛР №6):

1. `hJob = CreateJobObject(NULL, NULL)` — создать объект;
2. `AssignProcessToJobObject(hJob, hProcess)` — включить процесс (проще всего, если он
   создан приостановленным: флаг `CREATE_SUSPENDED`, затем `ResumeThread`);
3. все процессы, которые включённый в Job процесс породит *после этого*, попадают в
   тот же Job автоматически;
4. `TerminateJobObject` — уничтожить всех; `CloseHandle(hJob)` — закрыть хэндл.

**Хэндлы и идентификаторы.** Хэндл процесса нужен для управления им (`TerminateProcess`,
`WaitForSingleObject`, `GetExitCodeProcess`); идентификатор (PID) — число, под которым
процесс виден в системе (диспетчер задач).

## 3. Формулировка задания

**Базовый вариант.** Разработать пять программ: процесс-родитель, два дочерних процесса
и два «внучатых» (по одному потомку у каждого дочернего). Все выводят сообщения о своём
«родственном» положении и номере шага цикла (10–20 повторений, паузы 1–2 с, у разных
программ разные — отличаются на 30–70 %). На 7-м шаге родитель уничтожает первую
дочернюю (и выводит об этом сообщение), на 11-м — вторую дочернюю и её потомка. Каждая
программа, создающая процесс, передаёт ему текстовое имя; имя выводится каждым процессом,
кроме родителя, с примечанием.

**Усложнённый вариант.** Каждый дочерний процесс передаёт своему потомку не только его имя,
но и своё собственное; потомок сообщает оба имени (по аналогии с отчеством).

*Трактовки.* (1) Первая дочерняя уничтожается функцией `TerminateProcess`, поэтому
*её потомок продолжает работать* — это и демонстрируется (как в примере для Unix в
пособии, п. 7.3). Вторая дочерняя при запуске включается в Job, и на 11-м шаге
`TerminateJobObject` уничтожает её *вместе* с потомком. (2) Имена передаются в
командной строке; используются латинские имена (Alexey, Boris, Vasily, Grigory), так
как аргументы командной строки в `CreateProcess` — в ANSI-кодировке. (3) Процессы
запускаются в общей консоли, поэтому все сообщения видны в одном окне.

Паузы и число шагов:

| Процесс | Пауза, мс | Отличие от родителя | Шагов |
|---|---|---|---|
| Родитель | 1000 | — | 15 |
| Первый дочерний (Alexey) | 1400 | +40 % | 12 |
| Второй дочерний (Boris) | 1700 | +70 % | 12 |
| Потомок первого (Vasily) | 1300 | +30 % | 12 |
| Потомок второго (Grigory) | 1600 | +60 % | 12 |

## 4. Листинги

### 4.1. Общие функции (`lab06/common.h`)

```c
/*
 * ЛР №6: общие мелочи для всех программ (вывод одной строки с отметкой
 * времени и номером процесса). Подключается директивой #include "../common.h".
 */
#ifndef COMMON_H
#define COMMON_H

#include <windows.h>
#include <stdarg.h>
#include <stdio.h>

/* Консоль в UTF-8, чтобы русский текст из исходников выводился правильно. */
static inline void init_console(void)
{
    SetConsoleOutputCP(CP_UTF8);
}

/* Одна строка вывода: [время] PID | текст. Сразу сбрасываем буфер (fflush),
 * чтобы строки разных процессов, пишущих в одну консоль, не склеивались. */
static inline void say(const char *fmt, ...)
{
    char text[400];
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(text, sizeof(text), fmt, ap);
    va_end(ap);

    SYSTEMTIME t;
    GetLocalTime(&t);
    printf("[%02d:%02d:%02d] PID %-5lu | %s\n",
           t.wHour, t.wMinute, t.wSecond, GetCurrentProcessId(), text);
    fflush(stdout);
}

/* Запуск программы командной строкой cmd. Процесс использует консоль родителя
 * (общее окно). suspended = TRUE — создать в приостановленном состоянии
 * (нужно, чтобы успеть включить процесс в Job до начала его работы). */
static inline BOOL start_process(const char *cmd, BOOL suspended, PROCESS_INFORMATION *pi)
{
    char line[256];                          /* CreateProcess может менять строку */
    snprintf(line, sizeof(line), "%s", cmd);
    STARTUPINFO si;
    memset(&si, 0, sizeof(si));
    si.cb = sizeof(si);                      /* обязательно задать размер структуры */
    DWORD flags = NORMAL_PRIORITY_CLASS | (suspended ? CREATE_SUSPENDED : 0);
    return CreateProcess(NULL, line, NULL, NULL, FALSE, flags, NULL, NULL, &si, pi);
}

#endif
```

### 4.2. Родитель (`lab06/base/parent.c`, одинаков в обоих вариантах)

```c
/*
 * ЛР №6, базовый вариант: процесс-родитель.
 *
 * Запускает две дочерние программы (child1.exe, child2.exe), передавая каждой
 * текстовое имя. Затем выводит 15 сообщений о своём шаге с паузой 1 с.
 *   шаг 7  — уничтожает первую дочернюю функцией TerminateProcess
 *            (её потомок при этом продолжает работать);
 *   шаг 11 — уничтожает вторую дочернюю ВМЕСТЕ с её потомком: вторая дочерняя
 *            при запуске включена в объект Job, а TerminateJobObject
 *            уничтожает все процессы Job.
 *
 * Сборка:  gcc parent.c -o parent.exe -Wall
 * Запуск:  parent.exe   (child1.exe, child2.exe — рядом с ним)
 */
#include "../common.h"

#define STEPS    15
#define DELAY_MS 1000

int main(void)
{
    init_console();
    say("Родитель: начало работы.");

    PROCESS_INFORMATION pi1, pi2;

    /* Объект Job для второй ветви. Параметры (атрибуты защиты, имя) не нужны. */
    HANDLE job2 = CreateJobObject(NULL, NULL);
    if (!job2) { say("CreateJobObject: ошибка %lu", GetLastError()); return 1; }

    /* Первая дочерняя: обычный запуск, имя передаётся в командной строке. */
    if (!start_process("child1.exe Alexey", FALSE, &pi1)) {
        say("Не запустился child1.exe, ошибка %lu", GetLastError());
        return 1;
    }
    say("Родитель: запущен первый дочерний, имя Alexey, PID %lu.", pi1.dwProcessId);

    /* Вторая дочерняя: создаём приостановленной, включаем в Job и только затем
     * запускаем. Все процессы, которые она породит позже (потомок), автоматически
     * попадут в тот же Job. */
    if (!start_process("child2.exe Boris", TRUE, &pi2)) {
        say("Не запустился child2.exe, ошибка %lu", GetLastError());
        return 1;
    }
    if (!AssignProcessToJobObject(job2, pi2.hProcess)) {
        say("AssignProcessToJobObject: ошибка %lu", GetLastError());
        return 1;
    }
    ResumeThread(pi2.hThread);               /* теперь процесс начинает выполняться */
    say("Родитель: запущен второй дочерний, имя Boris, PID %lu (включён в Job).",
        pi2.dwProcessId);

    for (int k = 1; k <= STEPS; k++) {
        say("Родитель: шаг %d из %d.", k, STEPS);

        if (k == 7) {
            TerminateProcess(pi1.hProcess, 1);             /* только этот процесс */
            say("Родитель: приказ об уничтожении первого дочернего (PID %lu, TerminateProcess).",
                pi1.dwProcessId);
        }
        if (k == 11) {
            TerminateJobObject(job2, 1);                    /* все процессы Job */
            say("Родитель: приказ об уничтожении второго дочернего и его потомка (TerminateJobObject).");
        }
        Sleep(DELAY_MS);
    }

    /* Код завершения: у уничтоженных принудительно — тот, что мы задали (1). */
    DWORD c1 = 0, c2 = 0;
    GetExitCodeProcess(pi1.hProcess, &c1);
    GetExitCodeProcess(pi2.hProcess, &c2);
    say("Родитель: коды завершения дочерних: первый %lu, второй %lu. Конец работы.", c1, c2);

    CloseHandle(pi1.hProcess); CloseHandle(pi1.hThread);
    CloseHandle(pi2.hProcess); CloseHandle(pi2.hThread);
    CloseHandle(job2);
    return 0;
}
```

### 4.3. Базовый вариант: первая дочерняя и её потомок

```c
/*
 * ЛР №6, базовый вариант: первый дочерний процесс (child1.exe).
 *
 * Получает своё имя в командной строке (его назначил родитель), запускает
 * свой дочерний процесс grand1.exe (внука исходного родителя), назначая ему
 * имя Vasily и передавая его в командной строке, и выводит 12 сообщений о своём
 * шаге с паузой 1400 мс.
 *
 * Сборка:  gcc child1.c -o child1.exe -Wall
 */
#include "../common.h"

#define STEPS    12
#define DELAY_MS 1400

int main(int argc, char **argv)
{
    init_console();
    const char *myname = argc > 1 ? argv[1] : "(без имени)";
    say("Дочерний \"%s\": запущен. Имя мне назначил родитель.", myname);

    PROCESS_INFORMATION pi;
    if (start_process("grand1.exe Vasily", FALSE, &pi)) {
        say("Дочерний \"%s\": запустил своего потомка, имя Vasily, PID %lu.",
            myname, pi.dwProcessId);
        CloseHandle(pi.hProcess); CloseHandle(pi.hThread);   /* хэндлы больше не нужны */
    } else {
        say("Дочерний \"%s\": потомок не запустился, ошибка %lu.", myname, GetLastError());
    }

    for (int k = 1; k <= STEPS; k++) {
        say("Дочерний \"%s\": шаг %d из %d.", myname, k, STEPS);
        Sleep(DELAY_MS);
    }
    say("Дочерний \"%s\": конец работы.", myname);
    return 0;
}
```

### 4.4. Усложнённый вариант: первая дочерняя и её потомок

/*
 * ЛР №6, усложнённый вариант: первый дочерний процесс (child1.exe).
 *
 * Отличие от базового: потомку передаётся не только его имя (Vasily), но и
 * СОБСТВЕННОЕ имя этого процесса — как отчество в русском языке.

        Sleep(DELAY_MS);

## 6. Объяснение результатов

1. **Родство и имена.** Родитель (PID 23692) запустил Alexey (19480) и Boris (9380) и
   передал им имена в командной строке; каждый из них запустил своего потомка
   (Vasily — 25032, Grigory — 17244). Каждый выводит своё имя с примечанием, кто его
   назначил. В усложнённом варианте потомок выводит ещё и имя родителя: «Внук "Vasily"
   (родитель "Alexey")».
2. **Паузы разные**, поэтому строки разных процессов чередуются неупорядоченно: процессы
   работают параллельно и независимо друг от друга, выводя в общую консоль.
3. **Шаг 7 — `TerminateProcess` для Alexey.** После сообщения родителя (23:43:06) Alexey
   больше ничего не выводит (его шаг 5 был последним). Но Vasily (его потомок) продолжает
   выводить шаги 6…12 и завершается самостоятельно: уничтожение процесса не затрагивает
   его потомков, они становятся «осиротевшими» (при большем числе шагов Vasily продолжал бы
   работать и после завершения родителя).
4. **Шаг 11 — `TerminateJobObject`.** После сообщения родителя (23:43:10) пропадают
   *оба* процесса второй ветви: Boris (последняя строка — шаг 6) и его потомок Grigory
   (последняя строка — шаг 7). Это стало возможным потому, что Boris был включён в Job до
   начала работы (`CREATE_SUSPENDED` → `AssignProcessToJobObject` → `ResumeThread`), а
   значит, все созданные им процессы тоже оказались в Job.
5. **Коды завершения.** `GetExitCodeProcess` вернул 1 для обоих уничтоженных
   процессов — это значение мы сами задали вторым параметром `TerminateProcess` /

6. **Общая консоль.** Дочерние процессы создаются с `bInheritHandles = FALSE`, но

## 7. Ответы на контрольные вопросы

**1. Объясните, чем принципиально отличаются идентификаторы системных объектов от
хэндлов, приведите пример использования тех и других в ОС Windows.**
Хэндл — номер строки в таблице управляющих блоков конкретного процесса. Он имеет смысл
только внутри этого процесса: в разных процессах одинаковые значения хэндлов обозначают
разные объекты, а на один объект могут указывать несколько хэндлов (например, после
`DuplicateHandle`). Идентификатор — уникальное в пределах системы обозначение сложного
объекта (процесса, нити): он один и тот же для всех, пока объект существует. Пример: в
`PROCESS_INFORMATION` после `CreateProcess` возвращаются `hProcess` — хэндл, который
родитель использует в `TerminateProcess`, `GetExitCodeProcess`, `AssignProcessToJobObject`,
и `dwProcessId` — идентификатор, который выводится в сообщениях и виден в диспетчере задач.

**2. Какая информация возвращается в родительскую программу после создания нового
процесса с помощью функции CreateProcess?**
Функция возвращает значение `BOOL` (удалось ли создать процесс; при неудаче причину
даёт `GetLastError`) и заполняет структуру `PROCESS_INFORMATION`: `hProcess` — хэндл
нового процесса, `hThread` — хэндл его главной нити, `dwProcessId` — идентификатор
процесса, `dwThreadId` — идентификатор нити.

**3. Как создать новый процесс, чтобы он использовал для вывода текстовую консоль,
отличную от той, которую использует родительский процесс?**
Указать в параметре флагов создания (`CreateFlag`) функции `CreateProcess` константу
`CREATE_NEW_CONSOLE`: для нового процесса будет создано новое консольное окно. Без неё
(как в нашей работе) дочерний процесс использует консоль родителя.

**4. Что произойдёт после закрытия хэндла дочернего процесса, выполненного
родительским процессом, как это повлияет на сам дочерний процесс?**
Дочерний процесс на закрытие хэндла никак не реагирует и продолжает работать.
Родитель же теряет способ управлять им через этот хэндл (завершать, ждать, получить код
завершения). Управляющий блок процесса в системе освобождается, когда не осталось
хэндлов на него (и сам процесс завершился); если хэндл единственный, то он ликвидируется
сразу при закрытии, как и описано в пособии (п. 7.2), где после запуска хэндлы
закрываются `CloseHandle(pi.hProcess); CloseHandle(pi.hThread)`.
