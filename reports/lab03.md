## 1. Цель работы

Изучить многопользовательскую блокировку (запрет совместного использования)
файлов в Windows.

## 2. Краткие теоретические сведения

**Проблема одновременного доступа.** Несколько одновременно работающих программ
могут обращаться к одному файлу. Если две из них пишут в него одновременно, данные
перемешиваются в непредусмотренном порядке (как два преподавателя, пишущие на одной
доске). Поэтому ОС предоставляет средства ограничения одновременного использования
файлов (учебное пособие, п. 2.4; методические указания, ЛР №3).

**Два подхода в Windows.**

1. *Режим разделения при открытии.* Третий аргумент функции `CreateFile` —
   `ShareMode`. Константы `FILE_SHARE_READ` и `FILE_SHARE_WRITE` разрешают другим
   процессам читать и (или) писать в файл, пока он открыт нами. Если задать `0`,
   файл становится недоступным для остальных, и запрет действует, пока наш процесс не
   закроет файл (`CloseHandle`).
2. *Блокировка участка файла.* Функции `LockFile` / `UnlockFile` (и
   расширенные `LockFileEx` / `UnlockFileEx`) закрывают не весь файл, а заданный участок.
   `LockFile` не ждёт: если участок занят, она сразу возвращает 0, и ожидание
   программист организует сам.

**Ошибки.** В Windows нет единого способа сообщать об ошибках: разные функции
возвращают `BOOL`, `HANDLE`, `NULL`, `INVALID_HANDLE_VALUE` и т. д. (таблица 1
методички). Если функция сообщила о неудаче, причину узнают вызовом
`GetLastError()` и сравнивают с кодами из `winerror.h`. Для файлов важны:
`ERROR_FILE_NOT_FOUND` (2), `ERROR_PATH_NOT_FOUND` (3) и
`ERROR_SHARING_VIOLATION` (32 — файл занят другим процессом из-за режима
разделения).

**Вывод в консоль.** Цвет и позиция задаются отдельно от текста (пособие, п. 4.1–4.3):
`GetConsoleScreenBufferInfo` даёт размер окна (`srWindow`), `FillConsoleOutputAttribute`
задаёт цвет участка экрана (константы `FOREGROUND_RED/GREEN/BLUE/INTENSITY`),
`WriteConsoleOutputCharacter` выводит текст в произвольную позицию.

**Пакетные файлы.** В `cmd` нет команды `sleep`; задержку получают пингом петлевого
интерфейса: `ping 127.0.0.1 -n N >nul` занимает примерно N−1 секунд (пакеты уходят
раз в секунду), вывод скрывается перенаправлением в `nul`.

## 3. Формулировка задания

**Базовый вариант.** Программа для Windows запускается в двух экземплярах — каждый в
своём окне командной оболочки или из Проводника. Она использует заранее
подготовленный текстовый файл. Пытается открыть его для чтения с запретом
использования файла другими. На экран выводится сообщение, удалось ли открыть файл,
а если не удалось из-за недоступности по причине одновременно выполняющейся
программы — сообщение именно об этой причине. Если файла нет — сообщение и
завершение. Если файл есть, но заблокирован другим экземпляром — ожидание
освобождения. В обоих случаях программа читает из файла все данные и выводит их на
экран. Сообщения цветные и в середине консольного окна.

**Усложнённый вариант.** Командный (пакетный) файл для автоматического запуска трёх
экземпляров программы с интервалами запуска 3–4 секунды.

*Трактовка.* Задание не требует, чтобы программа удерживала файл после чтения, но без
этого запрет невозможно увидеть: чтение маленького файла занимает микросекунды.
Поэтому после чтения программа держит файл открытым 8 секунд (`HOLD_MS`) и только
затем закрывает его — как в упражнении 5 учебного пособия («задержка перед
прекращением запрета на несколько секунд»).

## 4. Листинги

### 4.1. Программа (`lab03/lab3.c`)

```c
/*
 * ЛР №3, базовый вариант (Windows): открытие файла с запретом совместного
 * доступа и ожидание его освобождения другим экземпляром программы.
 *
 *  1. Программа открывает text.txt для чтения, указав в CreateFile режим
 *     разделения 0 — другим процессам файл становится недоступен.
 *  2. Если файла нет — сообщение и завершение.
 *  3. Если файл занят другим экземпляром (ERROR_SHARING_VIOLATION) — сообщение
 *     об этой причине и ожидание освобождения (повторные попытки открытия).
 *  4. После открытия читает весь файл и выводит его на экран. Файл удерживается
 *     HOLD_MS мс (чтобы запрет был виден другим экземплярам), затем закрывается.
 *
 * Сообщения — цветные, по центру окна консоли. Если вывод переадресован (не
 * консоль), сообщения выводятся обычным текстом.
 *
 * Сборка:  gcc lab3.c -o lab3.exe -Wall
 * Запуск:  два-три экземпляра в разных окнах (или lab3_run.bat)
 */
#include <windows.h>
#include <stdarg.h>
#include <stdio.h>
#include <string.h>

#define FNAME    "text.txt"
#define HOLD_MS  8000   /* сколько держим файл открытым после чтения */
#define RETRY_MS 300    /* период повторных попыток открытия */

/* Цвета сообщений: комбинации констант FOREGROUND_* (см. пособие, п. 4.2). */
#define C_INFO (FOREGROUND_GREEN | FOREGROUND_BLUE | FOREGROUND_INTENSITY)   /* голубой */
#define C_OK   (FOREGROUND_GREEN | FOREGROUND_INTENSITY)                     /* зелёный */
#define C_WAIT (FOREGROUND_RED | FOREGROUND_GREEN | FOREGROUND_INTENSITY)    /* жёлтый */
#define C_ERR  (FOREGROUND_RED | FOREGROUND_INTENSITY)                       /* красный */
#define C_DATA (FOREGROUND_RED | FOREGROUND_GREEN | FOREGROUND_BLUE | FOREGROUND_INTENSITY) /* белый */

static HANDLE hOut;         /* хэндл экрана консоли */
static BOOL   isConsole;    /* вывод идёт в консоль (а не в файл/канал)? */
static SMALL_RECT win;      /* видимая часть буфера: окно консоли */
static WORD   defAttr;      /* исходный цвет консоли */
static int    nextRow;      /* строка экрана для следующего сообщения */

/* Подготовка экрана: узнаём размер окна, очищаем его, выбираем стартовую
 * строку так, чтобы блок сообщений приходился на середину окна. */
static void init_screen(void)
{
    CONSOLE_SCREEN_BUFFER_INFO bi;
    SetConsoleOutputCP(CP_UTF8);                         /* для printf с русским текстом */
    hOut = GetStdHandle(STD_OUTPUT_HANDLE);
    isConsole = GetConsoleScreenBufferInfo(hOut, &bi);   /* для файла/канала вернёт 0 */
    if (!isConsole) return;

    win = bi.srWindow;
    defAttr = bi.wAttributes;
    int width = win.Right - win.Left + 1;
    DWORD n;
    for (int y = win.Top; y <= win.Bottom; y++) {        /* очистка видимой области */
        COORD c = { win.Left, (SHORT)y };
        FillConsoleOutputCharacterW(hOut, L' ', width, c, &n);
        FillConsoleOutputAttribute(hOut, defAttr, width, c, &n);
    }
    nextRow = (win.Top + win.Bottom) / 2 - 4;
    if (nextRow < win.Top) nextRow = win.Top;
}

/* Выводит одно сообщение цветом attr с отметкой времени.
 * В консоли — по центру очередной строки; иначе — просто строкой в stdout. */
static void say(WORD attr, const char *fmt, ...)
{
    char text[512], line[560];
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(text, sizeof(text), fmt, ap);
    va_end(ap);

    SYSTEMTIME t;
    GetLocalTime(&t);
    snprintf(line, sizeof(line), "[%02d:%02d:%02d] %s", t.wHour, t.wMinute, t.wSecond, text);

    if (!isConsole) {                                    /* переадресованный вывод */
        DWORD w;
        strcat(line, "\r\n");
        WriteFile(hOut, line, (DWORD)strlen(line), &w, NULL);
        return;
    }

    wchar_t wide[560];
    int len = MultiByteToWideChar(CP_UTF8, 0, line, -1, wide, 560) - 1;  /* без '\0' */
    int width = win.Right - win.Left + 1;
    if (len > width) len = width;

    int row = nextRow < win.Bottom ? nextRow++ : win.Bottom - 1;   /* ниже окна не уходим */
    COORD pos = { (SHORT)(win.Left + (width - len) / 2), (SHORT)row };   /* по центру */
    DWORD n;
    FillConsoleOutputAttribute(hOut, attr, len, pos, &n);        /* цвет для этих позиций */
    WriteConsoleOutputCharacterW(hOut, wide, len, pos, &n);      /* сам текст */
}

/* Выводит содержимое прочитанного файла построчно. */
static void show_data(char *data)
{
    for (char *p = strtok(data, "\n"); p; p = strtok(NULL, "\n")) {
        size_t l = strlen(p);
        if (l && p[l - 1] == '\r') p[l - 1] = '\0';
        if (*p) say(C_DATA, "%s", p);
    }
}

int main(void)
{
    init_screen();
    say(C_INFO, "Открываю файл \"" FNAME "\" с запретом совместного доступа...");

    HANDLE h;
    BOOL waited = FALSE;
    for (;;) {
        /* Третий аргумент — режим разделения. 0 = не разрешать другим ни чтение,
         * ни запись, пока файл открыт нами. */
        h = CreateFile(FNAME, GENERIC_READ, 0, NULL, OPEN_EXISTING,
                       FILE_ATTRIBUTE_NORMAL, NULL);
        if (h != INVALID_HANDLE_VALUE) break;

        DWORD err = GetLastError();               /* причина неудачи */
        if (err == ERROR_FILE_NOT_FOUND || err == ERROR_PATH_NOT_FOUND) {
            say(C_ERR, "Файл \"" FNAME "\" не найден (код %lu). Работа прекращена.", err);
            return 1;
        }
        if (err == ERROR_SHARING_VIOLATION) {     /* код 32: файл занят другим процессом */
            if (!waited)
                say(C_WAIT, "Файл занят другим экземпляром (код %lu). Жду освобождения...", err);
            waited = TRUE;
            Sleep(RETRY_MS);                       /* и пробуем снова */
            continue;
        }
        say(C_ERR, "Не удалось открыть файл, код ошибки %lu.", err);
        return 1;
    }

    say(C_OK, waited ? "Файл освободился, открыл его. Доступ другим запрещён."
                     : "Файл свободен, открыл его. Доступ другим запрещён.");

    char data[4096];
    DWORD got = 0;
    if (ReadFile(h, data, sizeof(data) - 1, &got, NULL)) {   /* весь небольшой файл за раз */
        data[got] = '\0';
        show_data(data);
    }

    say(C_INFO, "Держу файл %d с (чтобы запрет был заметен)...", HOLD_MS / 1000);
    Sleep(HOLD_MS);

    CloseHandle(h);       /* закрытие снимает запрет совместного доступа */
    say(C_OK, "Файл закрыт, запрет снят. Конец работы.");

    /* Если окно создано только для нашей программы (запуск из Проводника),
     * оно закроется сразу после завершения — ждём Enter, чтобы можно было
     * прочитать сообщения. При запуске из командной оболочки не ждём. */
    DWORD pids[2];
    if (isConsole && GetConsoleProcessList(pids, 2) == 1) {
        COORD end = { win.Left, win.Bottom };
        SetConsoleCursorPosition(hOut, end);
        printf("Нажмите Enter...");
        fflush(stdout);
        getchar();
    }
    return 0;
}
```

Сборка: `gcc lab03/lab3.c -o lab03/lab3.exe -Wall -Wextra` (предупреждений нет).

### 4.3. Командный файл (`lab03/lab3_run.bat`)

```bat
@echo off
rem Lab 3 (extended variant): start three copies of lab3.exe automatically,
rem about 3 seconds apart. (Comments are in English on purpose: cmd reads
rem .bat files in the OEM code page, and non-ASCII text breaks parsing.)
setlocal EnableDelayedExpansion

set COUNT=3
rem There is no sleep command in cmd, so ping of the loopback address is used:
rem one packet per second, hence "-n 4" gives a pause of about 3 seconds.
set PING_COUNT=4

for /l %%i in (1,1,%COUNT%) do (
    rem !time! (delayed expansion) is evaluated on every pass; %time% inside
    rem a loop would be substituted only once, before the loop starts.
    echo Starting instance %%i at !time!
    rem Each copy runs in its own window. "cmd /k" keeps the window open
    rem after the program ends so the messages can be read.
    start "lab3 instance %%i" cmd /k .\lab3.exe
    if %%i lss %COUNT% ping 127.0.0.1 -n %PING_COUNT% >nul
)

echo All instances started.
endlocal
```

## 6. Объяснение результатов

1. **Запрет совместного доступа.** Экземпляр A вызвал `CreateFile` с
   `ShareMode = 0`, поэтому пока он держит файл открытым, любая другая попытка
   открыть этот файл (даже только для чтения) завершается неудачей. Функция возвращает
   `INVALID_HANDLE_VALUE`, а `GetLastError()` — 32, `ERROR_SHARING_VIOLATION`.
   Программа проверяет именно этот код и пишет, что причина — занятость файла
   другим экземпляром.
2. **Ожидание.** `CreateFile` не умеет ждать, поэтому B и C повторяют попытку каждые
   300 мс (`RETRY_MS`), пока файл не освободится. Это самый простой, хотя и не самый
   экономный способ (пособие, п. 2.4, называет его «простейшим, но не эффективным»).
3. **Освобождение.** В 23:23:50 A закрыл файл (`CloseHandle`), запрет исчез, и первая
   же успешная попытка сработала у C (23:23:50), затем C держал файл 8 с, и только после
   его закрытия файл получил B (23:23:58). То есть порядок получения файла после
   освобождения определяется тем, чья попытка выполнится первой, а не очередью:
   так как B начал ждать раньше C, «справедливого» порядка здесь нет. В Linux при
   ожидании через `F_SETLKW` опрос не нужен: процесс блокируется в ядре и
   возобновляется, когда блокировка снята (ЛР №4).
4. **Отсутствие файла.** Если файла нет, `GetLastError()` возвращает
   `ERROR_FILE_NOT_FOUND` (2), и программа сразу заканчивает работу — ждать
   бессмысленно.
5. **Цвет и положение.** Сообщения выводятся парой `FillConsoleOutputAttribute` +
   `WriteConsoleOutputCharacter` в рассчитанную позицию: колонка — по центру ширины
   окна (`srWindow`), строки — начиная примерно с середины высоты окна.
   При переадресации вывода в файл `GetConsoleScreenBufferInfo` возвращает ошибку, и
   программа печатает текст обычным образом (5.6).
6. **Пакетный файл.** Три экземпляра запущены с интервалом около 3,1 с (пауза
   `ping -n 4`). Внутри цикла время берётся через `!time!`: запись `%time%` внутри
   `for` подставилась бы один раз до начала цикла, и все строки показали бы одно и то
   же время. Для этого включено `EnableDelayedExpansion`.

## 7. Ответы на контрольные вопросы

**1. Чем стандартный ввод-вывод отличается от нестандартного, привести примеры
использования того и другого.**
Стандартные потоки (ввод, вывод, ошибки) открывает сама ОС перед запуском программы:
в Unix им отведены номера 0, 1, 2, в Windows хэндлы запрашивают через
`GetStdHandle`. Их можно перенаправить в командной строке (`<`, `>`, `2>`) без изменения
программы. Нестандартный ввод-вывод — это файлы, которые программа сама открывает по
имени (`open`, `CreateFile`) и получает хэндл от функции открытия; они требуют явного
закрытия, для них можно задавать режимы доступа и разделения. Пример стандартного:
программа-фильтр, читающая `stdin` и пишущая в `stdout`, использование в конвейерах.
Пример нестандартного: данные приложения хранятся в файле `text.txt` (как в этой работе).

**2. Зачем в общем случае закрывать файл, к каким возможным последствиям и когда
приводит не закрытие файла.**
Закрытие уничтожает управляющий блок, освобождает хэндл и снимает ограничения
доступа, установленные процессом. Если файл не закрыт, пока процесс работает, он
остаётся занятым: в нашем случае другие экземпляры получали бы
`ERROR_SHARING_VIOLATION` до завершения процесса (запрет исчезает при закрытии файла
или завершении процесса). Кроме того, незакрытые хэндлы накапливаются (их число
ограничено) и незаписанные данные могут не дойти до файла.

**3. Какой код ошибки возвращает функция открытия файла, если в ней задано
ограничение по одновременной работе с файлом и этот файл в момент выполнения попытки
открытия уже захвачен для работы другим вычислительным процессом.**
Сама `CreateFile` возвращает `INVALID_HANDLE_VALUE`, а код причины, получаемый
вызовом `GetLastError()`, — `ERROR_SHARING_VIOLATION`, числовое значение 32 (0x20). Это
подтверждают сообщения программы: «Файл занят другим экземпляром (код 32)».
(Не следует путать с `ERROR_LOCK_VIOLATION`, код 33: он возникает при обращении к
участку, заблокированному функцией `LockFile`.)
