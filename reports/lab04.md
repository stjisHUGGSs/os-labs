## 1. Цель работы

Изучить многопользовательскую блокировку файлов в Linux.

## 2. Краткие теоретические сведения

**Права доступа и блокировки — разные вещи.** В Unix/Linux доступ к файлу определяется
правами: для владельца (user), группы (group) и остальных (other) отдельно
устанавливаются права на чтение (r), запись (w) и выполнение (x) — девять бит, которые
удобно записывать восьмеричным числом (например, `0600` — чтение и запись только
владельцу). Права задаются при создании файла: `open(имя, O_CREAT, 0600)`.
Ограничение же *одновременной* работы с файлом — отдельная задача.

**Блокировка через `fcntl`.** Системная функция `fcntl(handle, cmd, struct flock *lock)`
с командами:

* `F_SETLK` — попытаться установить (или снять, если `l_type = F_UNLCK`) блокировку и
  сразу вернуть управление; при неудаче возвращает `-1`;
* `F_SETLKW` — то же, но при невозможности установить блокировку процесс *ожидает*
  (W — Wait);
* `F_GETLK` — узнать, какая блокировка мешает (в структуре возвращается, в том числе,
  `l_pid` — PID процесса, который держит блокировку).

Структура `flock` описывает блокируемый участок: `l_type` (`F_RDLCK` — блокировка по
чтению, `F_WRLCK` — по записи, `F_UNLCK` — снятие), `l_whence` (`SEEK_SET`,
`SEEK_CUR`, `SEEK_END` — от чего отсчитывать), `l_start` (смещение) и `l_len` (длина,
`0` — до конца файла).

Блокировка по чтению может быть установлена несколькими процессами одновременно и
лишь мешает другим установить блокировку по записи. Блокировка по записи — только
одна, она запрещает любые другие блокировки участка. Для блокировки по записи файл
должен быть открыт на запись (`O_WRONLY` или `O_RDWR`), для блокировки по чтению — на
чтение. Блокировки в Unix *рекомендательные*: они действуют лишь на программы,
которые сами вызывают `fcntl`; обычные `read`/`write` блокировка не останавливает
(пособие, п. 2.4).

**Управление экраном в Linux.** Позиция и цвет задаются управляющими
последовательностями ANSI, которые передаются в потоке вывода вместе с текстом: символ
`ESC` (код 27, в Си — `\033`), затем `[`, параметры и буква-команда.
`ESC[строка;столбецH` — позиция курсора (нумерация с 1), `ESC[2J` — очистка экрана,
`ESC[цветm` — цвет (30–37 — цвет текста, 40–47 — фон, 1 — повышенная яркость),
`ESC[0m` — сброс. Размер терминала узнаётся вызовом `ioctl(…, TIOCGWINSZ, …)`.

## 3. Формулировка задания

**Базовый вариант.** Программа для Linux запускается в двух экземплярах, каждый в своей
виртуальной консоли. Она использует заранее подготовленный текстовый файл, открывает
его (при невозможности — сообщение и завершение). После открытия пытается установить на
весь файл блокировку по записи; по результату выводит сообщение о том, удалось ли.
Если сразу не удалось — задаёт блокировку с ожиданием. После установки блокировки читает
файл, выводит данные на экран, «засыпает» на 7 или 8 секунд и снимает блокировку.
Сообщения цветные и в середине экрана.

**Усложнённый вариант.** Командный файл Linux для автоматического запуска трёх
экземпляров программы с интервалами 3 или 4 секунды.

*Трактовка.* Блокировка по записи требует, чтобы файл был открыт на запись, поэтому
файл открывается в режиме `O_RDWR`, хотя программа его только читает. Чтобы
экземпляры могли нормально работать на одном экране, окна для них создаёт `tmux`
(окно `tmux` — аналог отдельной виртуальной консоли).

## 4. Листинги

### 4.1. Программа (`lab04/lab4.c`)

```c
/*
 * ЛР №4, базовый вариант (Linux): блокировка файла по записи через fcntl.
 *
 *  1. Открывает text.txt (нет файла — сообщение и выход).
 *  2. Пытается сразу поставить блокировку по записи на весь файл (F_SETLK).
 *  3. Если файл заблокирован другим процессом — сообщает об этом (с PID
 *     владельца, его даёт F_GETLK) и ставит блокировку с ожиданием (F_SETLKW).
 *  4. Читает весь файл, выводит на экран, «засыпает» на SLEEP_SEC секунд,
 *     снимает блокировку, закрывает файл.
 *
 * Сообщения цветные (управляющие последовательности ANSI) и по центру экрана.
 * Если вывод переадресован (не терминал), сообщения идут обычными строками.
 *
 * Сборка:  gcc lab4.c -o lab4.out -Wall
 * Запуск:  по экземпляру в каждой консоли, либо ./lab4_run.sh
 */
#include <errno.h>
#include <fcntl.h>
#include <stdarg.h>
#include <stdio.h>
#include <string.h>
#include <sys/ioctl.h>   /* ioctl, TIOCGWINSZ — размер терминала */
#include <time.h>
#include <unistd.h>

#define FNAME     "text.txt"
#define SLEEP_SEC 7          /* по заданию 7 или 8 секунд */

/* Цвета: параметры управляющей последовательности ESC[...m (пособие, табл. 4.1) */
#define C_INFO "1;36"   /* ярко-бирюзовый */
#define C_OK   "1;32"   /* ярко-зелёный */
#define C_WAIT "1;33"   /* ярко-жёлтый */
#define C_ERR  "1;31"   /* ярко-красный */
#define C_DATA "1;37"   /* ярко-белый */

static int rows = 24, cols = 80;   /* размер экрана (по умолчанию, если не терминал) */
static int is_tty;
static int next_row;               /* строка для следующего сообщения */

/* Число символов (не байтов) в UTF-8 строке — для расчёта центрирования. */
static int utf8_len(const char *s)
{
    int n = 0;
    for (; *s; s++)
        if (((unsigned char)*s & 0xC0) != 0x80) n++;   /* пропускаем байты-продолжения */
    return n;
}

/* Подготовка экрана: узнаём размер, очищаем (ESC[2J), выбираем стартовую строку
 * так, чтобы блок сообщений пришёлся на середину. */
static void init_screen(void)
{
    struct winsize ws;
    is_tty = isatty(STDOUT_FILENO);
    if (is_tty && ioctl(STDOUT_FILENO, TIOCGWINSZ, &ws) == 0 && ws.ws_row > 0) {
        rows = ws.ws_row;
        cols = ws.ws_col;
        dprintf(STDOUT_FILENO, "\033[2J");
    }
    next_row = rows / 2 - 4;
    if (next_row < 1) next_row = 1;
}

/* Одно цветное сообщение по центру очередной строки (с отметкой времени). */
static void say(const char *color, const char *fmt, ...)
{
    char text[512], line[560];
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(text, sizeof(text), fmt, ap);
    va_end(ap);

    time_t now = time(NULL);
    struct tm tm;
    localtime_r(&now, &tm);
    snprintf(line, sizeof(line), "[%02d:%02d:%02d] %s", tm.tm_hour, tm.tm_min, tm.tm_sec, text);

    if (!is_tty) {                       /* вывод в файл/канал — обычная строка */
        dprintf(STDOUT_FILENO, "%s\n", line);
        return;
    }
    int len = utf8_len(line);
    int col = (cols - len) / 2 + 1;      /* ANSI-координаты начинаются с 1 */
    if (col < 1) col = 1;
    int row = next_row < rows - 1 ? next_row++ : rows - 1;
    /* ESC[строка;столбецH — позиция; ESC[цвет m — цвет; ESC[0m — сброс цвета.
     * Всё одним вызовом, чтобы позиция и цвет не «разорвались» с текстом. */
    dprintf(STDOUT_FILENO, "\033[%d;%dH\033[%sm%s\033[0m", row, col, color, line);
}

int main(void)
{
    init_screen();
    say(C_INFO, "Открываю файл \"" FNAME "\"...");

    /* Блокировка по записи (F_WRLCK) возможна только для файла, открытого на запись,
     * поэтому режим O_RDWR, хотя программа только читает. */
    int fd = open(FNAME, O_RDWR);
    if (fd == -1) {
        say(C_ERR, "Не удалось открыть файл: %s. Работа прекращена.", strerror(errno));
        dprintf(STDOUT_FILENO, "\033[%d;1H\n", rows);
        return 1;
    }

    /* Описание блокируемого участка: весь файл (l_start = 0, l_len = 0 — до конца). */
    struct flock lk = { .l_type = F_WRLCK, .l_whence = SEEK_SET, .l_start = 0, .l_len = 0 };

    /* Попытка без ожидания. Успех — 0, неудача — -1 (errno = EACCES или EAGAIN). */
    if (fcntl(fd, F_SETLK, &lk) == 0) {
        say(C_OK, "Блокировка по записи установлена сразу.");
    } else {
        /* Выясняем, кто держит блокировку: F_GETLK заполняет lk описанием
         * первой мешающей блокировки, в том числе l_pid — PID владельца. */
        struct flock who = lk;
        if (fcntl(fd, F_GETLK, &who) == 0 && who.l_type != F_UNLCK)
            say(C_WAIT, "Файл заблокирован процессом %d. Жду освобождения...", (int)who.l_pid);
        else
            say(C_WAIT, "Файл заблокирован другим процессом. Жду освобождения...");

        /* Блокировка с ожиданием: процесс «засыпает» внутри fcntl до освобождения. */
        lk.l_type = F_WRLCK;
        if (fcntl(fd, F_SETLKW, &lk) == -1) {
            say(C_ERR, "Ошибка fcntl: %s", strerror(errno));
            return 1;
        }
        say(C_OK, "Дождался. Блокировка по записи установлена.");
    }

    /* Чтение всего файла (маленького) и вывод построчно. */
    char data[4096];
    ssize_t n = read(fd, data, sizeof(data) - 1);
    if (n > 0) {
        data[n] = '\0';
        for (char *p = strtok(data, "\n"); p; p = strtok(NULL, "\n"))
            say(C_DATA, "%s", p);
    }

    say(C_INFO, "Сплю %d с, не снимая блокировку...", SLEEP_SEC);
    sleep(SLEEP_SEC);

    /* Снятие блокировки: тот же участок, тип F_UNLCK. Блокировка и так исчезла бы
     * при закрытии файла или завершении процесса. */
    lk.l_type = F_UNLCK;
    fcntl(fd, F_SETLK, &lk);
    close(fd);
    say(C_OK, "Блокировка снята, файл закрыт. Конец работы.");

    if (is_tty) dprintf(STDOUT_FILENO, "\033[%d;1H\n", rows);   /* курсор под блок */
    return 0;
}
```

Сборка: `gcc lab04/lab4.c -o lab04/lab4.out -Wall -Wextra` (предупреждений нет).

### 4.3. Командный файл (`lab04/lab4_run.sh`)

```bash
#!/bin/bash
# ЛР №4, усложнённый вариант: автоматический запуск трёх экземпляров
# lab4.out с интервалом 3 секунды между ними.
#
# Программа рисует сообщения по абсолютным координатам экрана, поэтому каждому
# экземпляру нужна своя консоль. Роль «виртуальных консолей» играют окна tmux:
# переключение между ними — Ctrl-b n / Ctrl-b p, отключиться — Ctrl-b d.
# Если tmux нет, экземпляры запускаются в фоне, а вывод идёт в файлы lab4_N.log.

COUNT=3      # сколько экземпляров
DELAY=3      # пауза между запусками, секунд (по заданию 3 или 4)
SESSION=lab4

cd "$(dirname "$0")" || exit 1
[ -x ./lab4.out ] || gcc lab4.c -o lab4.out -Wall || exit 1   # собрать, если ещё не собрано

if command -v tmux >/dev/null 2>&1; then
    tmux kill-session -t "$SESSION" 2>/dev/null            # убрать сеанс от прошлого запуска
    tmux new-session -d -s "$SESSION" -n inst1 -x 120 -y 36 # сеанс; в нём окно 1
    for i in $(seq 1 "$COUNT"); do
        [ "$i" -gt 1 ] && tmux new-window -t "$SESSION" -n "inst$i"   # окно для экземпляра i
        tmux send-keys -t "$SESSION:inst$i" "./lab4.out" Enter        # запустить в этом окне
        echo "Экземпляр $i запущен в $(date +%T)"
        [ "$i" -lt "$COUNT" ] && sleep "$DELAY"                       # пауза до следующего
    done
    echo "Все экземпляры запущены (tmux, сеанс $SESSION)."
    [ -t 0 ] && tmux attach -t "$SESSION"                  # показать, если запущено из терминала
else
    for i in $(seq 1 "$COUNT"); do
        ./lab4.out > "lab4_$i.log" 2>&1 &                  # фон, вывод в файл
        echo "Экземпляр $i запущен в $(date +%T), вывод: lab4_$i.log"
        [ "$i" -lt "$COUNT" ] && sleep "$DELAY"
    done
    wait
fi
```

## 6. Объяснение результатов

1. **Установка блокировки.** Первый экземпляр вызвал `fcntl(fd, F_SETLK, &lk)` с
   `l_type = F_WRLCK`, `l_start = 0`, `l_len = 0` (весь файл) и получил 0 — блокировка
   установлена сразу (сообщение зелёным).
2. **Отказ и ожидание.** Второй и третий экземпляры получили от `F_SETLK` значение `-1`,
   так как участок уже заблокирован на запись. Они узнали владельца вызовом `F_GETLK`
   (PID 404 в выводе) и перешли к `F_SETLKW`: процесс остановился внутри `fcntl` и не
   тратит процессорное время на повторные попытки (в Windows приходилось повторять
   `CreateFile`, ЛР №3).
3. **Снятие.** Первый экземпляр проспал 7 с, снял блокировку (`F_UNLCK`) и закрыл файл.
   Ядро возобновило ожидающий экземпляр, он получил блокировку (сообщение
   «Дождался») и повторил то же самое. В данном прогоне экземпляры получили файл в порядке
   запуска, но стандарт этого порядка не гарантирует.
4. **Интервалы.** Экземпляры запущены с интервалом 3 с (23:35:36, 23:35:39, 23:35:42), а
   файл по очереди освобождался через 7 с (23:35:43, 23:35:50, 23:35:57).
5. **Цвет и положение.** Каждое сообщение выводится одним вызовом `dprintf`:
   `ESC[строка;столбецH` + `ESC[цветm` + текст + `ESC[0m`. Столбец рассчитан по размеру
   терминала из `ioctl(TIOCGWINSZ)` и числу *символов* строки (UTF-8: байты-продолжения
   не считаются), строка — от середины высоты экрана.
6. **Рекомендательность.** Блокировка действует только на программы, которые сами
   вызывают `fcntl`. Другой процесс, который просто откроет `text.txt` и вызовет `read`,
   прочитает файл несмотря на блокировку.

## 7. Ответы на контрольные вопросы

**1. Чем блокировка файла по записи в Windows отличается от блокировки по записи в
Linux.**
В Windows запрет задаётся режимом разделения в `CreateFile` (`ShareMode = 0`) или
функцией `LockFile` и действует *принудительно*: другой процесс, открывающий файл или
обращающийся к заблокированному участку, получает ошибку (`ERROR_SHARING_VIOLATION`,
`ERROR_LOCK_VIOLATION`). `LockFile` не различает чтение и запись и не ждёт — при занятости
возвращает 0, ожидание организует программист. В Linux блокировка по записи
(`F_WRLCK` в `fcntl`) *рекомендательная*: её учитывают только программы, которые сами
вызывают `fcntl`, обычные `read`/`write` она не останавливает. Зато возможна блокировка
участка с различием «по чтению»/«по записи» и ожидание средствами самой функции
(`F_SETLKW`), а также запрос владельца блокировки (`F_GETLK`).

**2. Чем блокировка файла по чтению в Windows отличается от блокировки по чтению в
Linux.**
В Linux блокировка по чтению (`F_RDLCK`) может быть установлена одновременно
несколькими процессами и лишь не даёт другим поставить блокировку по записи; для её
установки файл нужно открыть на чтение. В Windows `LockFile` не делит блокировки на
чтение и запись — участок закрывается для всех остальных целиком. Аналог разделяемой
блокировки по чтению даёт либо расширенная `LockFileEx` без флага
`LOCKFILE_EXCLUSIVE_LOCK` (блокировка разделяемая — её могут иметь несколько процессов),
либо режим открытия `FILE_SHARE_READ` без `FILE_SHARE_WRITE` (другие могут читать, но не
писать).

**3. Сформулируйте наиболее существенное отличие управлением цветом вывода на
консоль в Windows и Linux, оцените в каких условиях какое из этих решений кажется вам
предпочтительней.**
В Windows цвет и позиция — свойства экранного буфера консоли, которыми управляют
вызовами API над хэндлом экрана (`SetConsoleTextAttribute`, `FillConsoleOutputAttribute`,
`SetConsoleCursorPosition`), а текст выводится отдельно. В Linux цвет и позиция
задаются последовательностями ANSI, которые вставляются *в сам выводимый текст* и
обрабатываются терминалом; для этого не нужны никакие вызовы, кроме обычной записи.
Способ Windows нагляднее, позволяет перекрасить уже выведенный текст и не оставляет
служебных символов при переадресации вывода в файл (вызовы API на файле просто
не работают), но он громоздкий и работает только в Windows. Способ Linux компактный,
переносимый и работает по `ssh`, через канал и в любых терминалах, но результат не
очевиден по тексту программы, а при переадресации в файл управляющие символы попадают в
файл (поэтому в программе выполняется проверка `isatty`). Для программы, написанной
под Windows и рисующей на экране в разных местах, удобнее API; для переносимых
скриптов и утилит — последовательности ANSI.
