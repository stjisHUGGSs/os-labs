## 1. Цель работы

Научиться использовать в Windows информацию, предварительно выведенную на экран, —
читать с экрана символ в позиции, на которую указал пользователь щелчком мыши.

## 2. Краткие теоретические сведения

**События консоли.** Для текстовой консоли Windows операционная система формирует
*сообщения (события)*: нажатие и отпускание клавиши, действия мыши, изменение размера
окна, получение и потеря фокуса. Программа запрашивает очередное событие функцией

`BOOL ReadConsoleInput(HANDLE hConsInput, INPUT_RECORD *buffer, DWORD len, DWORD *actlen);`

Первый аргумент — хэндл консольного ввода (стандартного ввода), `buffer` — массив
записей `INPUT_RECORD`, `len` — их число (обычно 1), `actlen` — сколько записей получено.
Функция *блокирует* программу, пока не появится событие (пособие, п. 5.2).

**Структура события.** `INPUT_RECORD` содержит поле `EventType` (`KEY_EVENT`,
`MOUSE_EVENT`, `WINDOW_BUFFER_SIZE_EVENT`, `MENU_EVENT`, `FOCUS_EVENT`) и объединение
`Event`, строение которого зависит от типа. Для мыши это `MOUSE_EVENT_RECORD`:

* `dwMousePosition` — позиция (`X` — столбец, `Y` — строка);
* `dwButtonState` — битовая маска нажатых кнопок: `FROM_LEFT_1ST_BUTTON_PRESSED` (левая),
  `RIGHTMOST_BUTTON_PRESSED` (правая) и др.;
* `dwEventFlags` — `MOUSE_MOVED` (мышь двигалась), `DOUBLE_CLICK` (двойное нажатие);
* `dwControlKeyState` — состояние Shift, Ctrl, Alt и т. д.

**Режим консольного ввода.** `GetConsoleMode` / `SetConsoleMode` определяют, какие
события будут поступать: `ENABLE_MOUSE_INPUT` включает события мыши,
`ENABLE_PROCESSED_INPUT` сохраняет Ctrl-C. Прежний режим запоминают и в конце
восстанавливают; новый лучше получать как «прежний | нужный флаг».

**Чтение с экрана.** `ReadConsoleOutputCharacter` читает символы экранного буфера
(начиная с заданной позиции, указанное число), `ReadConsoleOutputAttribute` — их
атрибуты; для записи служат `WriteConsoleOutputCharacter` и `FillConsoleOutputAttribute`
(пособие, п. 4.2–4.4). В Unix стандартных средств чтения с экрана нет (в Linux для
этого есть устройство `/dev/vcs`).

## 3. Формулировка задания

**Базовый вариант.** Программа для Windows открывает текстовый файл для чтения и
выводит всё его содержимое в текстовую консоль. Затем запускается опрос мыши в
консольном режиме. По щелчку мышью на любом слове, находящемся в консоли, в последней
строке окна выводится буква, на которой выполнен щелчок, и координаты позиции
(номер строки и столбца). Информация выводится только для непустой позиции (для
пробелов — ничего). Действия повторяются многократно; завершение — по нажатию правой
кнопки мыши.

**Усложнённый вариант.** Вместо сведений о символе в последней строке — отобразить
этот символ *на своём месте*, но в другом регистре (строчные на прописные и наоборот),
одновременно перекрасив указанные мышью символы в яркий цвет (ярко-красный или
жёлтый). Координаты выводить не нужно.

*Трактовки.* «Последняя строка» — последняя строка видимого окна консоли
(`srWindow.Bottom`). Координаты выводятся так, как их возвращает система, — с нуля
(строка 0, столбец 0 — левый верхний угол); это указано в самом сообщении. Щелчок на
строке сообщений игнорируется.

## 4. Листинги

### 4.1. Базовый вариант (`lab05/lab5.c`)

```c
/*
 * ЛР №5, базовый вариант (Windows): события мыши в текстовой консоли.
 *
 *  - читает text.txt и выводит его содержимое в консоль;
 *  - включает приём событий мыши и в цикле читает их ReadConsoleInput;
 *  - по щелчку ЛЕВОЙ кнопкой на непустой позиции экрана в ПОСЛЕДНЕЙ строке окна
 *    выводит символ из этой позиции и его координаты (строка, столбец);
 *    на пробеле и пустом месте ничего не выводится;
 *  - щелчок ПРАВОЙ кнопкой завершает программу.
 *
 * Сборка:  gcc lab5.c -o lab5.exe -Wall
 */
#include <windows.h>
#include <stdio.h>
#include <string.h>

#define FNAME "text.txt"

static HANDLE hIn, hOut;

/* Загружает файл и выводит в консоль. Возвращает 0 при успехе. */
static int show_file(void)
{
    HANDLE f = CreateFile(FNAME, GENERIC_READ, FILE_SHARE_READ, NULL,
                          OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);
    if (f == INVALID_HANDLE_VALUE) return 1;
    char buf[4096];
    DWORD n = 0, w;
    ReadFile(f, buf, sizeof(buf), &n, NULL);
    CloseHandle(f);
    WriteFile(hOut, buf, n, &w, NULL);       /* консоль в UTF-8 (см. main) */
    return 0;
}

/* Выводит строку text в последнюю строку окна консоли цветом attr.
 * Старое содержимое этой строки предварительно стирается. */
static void status(int row, WORD defAttr, WORD attr, const wchar_t *text, int width)
{
    COORD pos = { 0, (SHORT)row };
    DWORD n;
    FillConsoleOutputCharacterW(hOut, L' ', width, pos, &n);   /* стереть строку */
    FillConsoleOutputAttribute(hOut, defAttr, width, pos, &n);
    int len = (int)wcslen(text);
    FillConsoleOutputAttribute(hOut, attr, len, pos, &n);      /* цвет для текста */
    WriteConsoleOutputCharacterW(hOut, text, len, pos, &n);    /* сам текст */
}

int main(void)
{
    SetConsoleOutputCP(CP_UTF8);
    hIn  = GetStdHandle(STD_INPUT_HANDLE);
    hOut = GetStdHandle(STD_OUTPUT_HANDLE);

    CONSOLE_SCREEN_BUFFER_INFO bi;
    if (!GetConsoleScreenBufferInfo(hOut, &bi)) {
        fprintf(stderr, "Нужна консоль: вывод не должен быть переадресован.\n");
        return 1;
    }
    if (show_file()) {
        printf("Не удалось открыть файл " FNAME "\n");
        return 1;
    }

    /* Режим консольного ввода. Запоминаем прежний, чтобы восстановить в конце.
     * ENABLE_MOUSE_INPUT — получать события мыши. ENABLE_EXTENDED_FLAGS нужен,
     * чтобы флаг QUICK_EDIT мог быть изменён: при включённом «быстром выделении»
     * щелчок мыши используется консолью для выделения текста и до программы
     * не доходит, поэтому этот флаг снимаем. */
    DWORD oldMode;
    GetConsoleMode(hIn, &oldMode);
    DWORD mode = (oldMode | ENABLE_MOUSE_INPUT | ENABLE_EXTENDED_FLAGS)
                 & ~ENABLE_QUICK_EDIT_MODE;
    if (!SetConsoleMode(hIn, mode)) return 1;

    int statusRow = bi.srWindow.Bottom;       /* последняя строка окна */
    int width = bi.dwSize.X;
    DWORD prevButtons = 0;                    /* состояние кнопок в прошлом событии */
    INPUT_RECORD rec;
    DWORD got;

    for (;;) {
        /* Вызов блокирует программу, пока не появится событие ввода. */
        if (!ReadConsoleInput(hIn, &rec, 1, &got) || got == 0) break;
        if (rec.EventType != MOUSE_EVENT) continue;    /* клавиши и др. не интересуют */

        MOUSE_EVENT_RECORD m = rec.Event.MouseEvent;
        DWORD pressed = m.dwButtonState & ~prevButtons;   /* кнопки, нажатые именно сейчас */
        prevButtons = m.dwButtonState;

        if (pressed & RIGHTMOST_BUTTON_PRESSED) break;    /* правая кнопка — выход */

        if (pressed & FROM_LEFT_1ST_BUTTON_PRESSED) {     /* нажатие левой кнопки */
            if (m.dwMousePosition.Y == statusRow) continue;   /* строка сообщений */

            /* Читаем с экрана один символ в позиции щелчка. */
            wchar_t ch = L' ';
            DWORD n;
            ReadConsoleOutputCharacterW(hOut, &ch, 1, m.dwMousePosition, &n);
            if (n == 0 || ch == L' ' || ch == 0) continue;   /* пусто — ничего не выводим */

            wchar_t msg[64];
            _snwprintf(msg, 64, L"Символ '%lc' (код %u), строка %d, столбец %d (с нуля)",
                       ch, (unsigned)ch, m.dwMousePosition.Y, m.dwMousePosition.X);
            status(statusRow, bi.wAttributes,
                   FOREGROUND_GREEN | FOREGROUND_INTENSITY, msg, width);
        }
    }

    SetConsoleMode(hIn, oldMode);              /* вернуть прежний режим */
    COORD end = { 0, (SHORT)statusRow };
    SetConsoleCursorPosition(hOut, end);
    printf("\n");
    return 0;
}
```

### 4.2. Усложнённый вариант (`lab05/lab5_ext.c`)

```c
/*
 * ЛР №5, усложнённый вариант (Windows): та же программа, но по щелчку левой
 * кнопкой вместо сведений о символе в последней строке сам символ ОТОБРАЖАЕТСЯ
 * НА СВОЁМ МЕСТЕ в другом регистре (строчная <-> прописная) и перекрашивается в
 * яркий цвет (ярко-красный). Координаты не выводятся. Правая кнопка — выход.
 *
 * Сборка:  gcc lab5_ext.c -o lab5_ext.exe -Wall
 */
#include <windows.h>
#include <stdio.h>

#define FNAME "text.txt"
#define BRIGHT_RED (FOREGROUND_RED | FOREGROUND_INTENSITY)   /* цвет перекрашенных символов */

static HANDLE hIn, hOut;

/* Загружает файл и выводит в консоль. Возвращает 0 при успехе. */
static int show_file(void)
{
    HANDLE f = CreateFile(FNAME, GENERIC_READ, FILE_SHARE_READ, NULL,
                          OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);
    if (f == INVALID_HANDLE_VALUE) return 1;
    char buf[4096];
    DWORD n = 0, w;
    ReadFile(f, buf, sizeof(buf), &n, NULL);
    CloseHandle(f);
    WriteFile(hOut, buf, n, &w, NULL);
    return 0;
}

/* Меняет регистр буквы. CharUpperW/CharLowerW знают не только латиницу, но и
 * кириллицу. Если символ — не буква (цифра, знак), он остаётся прежним. */
static wchar_t swap_case(wchar_t c)
{
    wchar_t up  = (wchar_t)(UINT_PTR)CharUpperW((LPWSTR)(UINT_PTR)c);
    wchar_t low = (wchar_t)(UINT_PTR)CharLowerW((LPWSTR)(UINT_PTR)c);
    if (c == low && c != up) return up;     /* была строчной -> делаем прописной */
    if (c == up && c != low) return low;    /* была прописной -> делаем строчной */
    return c;
}

int main(void)
{
    SetConsoleOutputCP(CP_UTF8);
    hIn  = GetStdHandle(STD_INPUT_HANDLE);
    hOut = GetStdHandle(STD_OUTPUT_HANDLE);

    CONSOLE_SCREEN_BUFFER_INFO bi;
    if (!GetConsoleScreenBufferInfo(hOut, &bi)) {
        fprintf(stderr, "Нужна консоль: вывод не должен быть переадресован.\n");
        return 1;
    }
    if (show_file()) {
        printf("Не удалось открыть файл " FNAME "\n");
        return 1;
    }

    /* Включаем мышь и снимаем «быстрое выделение» (оно перехватывает щелчки). */
    DWORD oldMode;
    GetConsoleMode(hIn, &oldMode);
    DWORD mode = (oldMode | ENABLE_MOUSE_INPUT | ENABLE_EXTENDED_FLAGS)
                 & ~ENABLE_QUICK_EDIT_MODE;
    if (!SetConsoleMode(hIn, mode)) return 1;

    DWORD prevButtons = 0;
    INPUT_RECORD rec;
    DWORD got;

    for (;;) {
        if (!ReadConsoleInput(hIn, &rec, 1, &got) || got == 0) break;
        if (rec.EventType != MOUSE_EVENT) continue;

        MOUSE_EVENT_RECORD m = rec.Event.MouseEvent;
        DWORD pressed = m.dwButtonState & ~prevButtons;   /* только что нажатые кнопки */
        prevButtons = m.dwButtonState;

        if (pressed & RIGHTMOST_BUTTON_PRESSED) break;    /* выход */

        if (pressed & FROM_LEFT_1ST_BUTTON_PRESSED) {
            wchar_t ch = L' ';
            DWORD n;
            ReadConsoleOutputCharacterW(hOut, &ch, 1, m.dwMousePosition, &n);
            if (n == 0 || ch == L' ' || ch == 0) continue;     /* пусто — пропускаем */

            wchar_t sw = swap_case(ch);
            /* На том же месте: сначала цвет, затем символ другого регистра. */
            FillConsoleOutputAttribute(hOut, BRIGHT_RED, 1, m.dwMousePosition, &n);
            WriteConsoleOutputCharacterW(hOut, &sw, 1, m.dwMousePosition, &n);
        }
    }

    SetConsoleMode(hIn, oldMode);
    COORD end = { 0, bi.srWindow.Bottom };
    SetConsoleCursorPosition(hOut, end);
    printf("\n");
    return 0;
}
```

## 6. Объяснение результатов

1. **Событийный цикл.** Программа большую часть времени находится в
   `ReadConsoleInput` и «спит» до появления события. Событие мыши приходит как запись
   `INPUT_RECORD` с `EventType == MOUSE_EVENT`; щелчок, движение и отпускание
   кнопки — это отдельные события, а клавиатурные события пропускаются.
2. **Что такое «нажатие».** Каждая запись содержит *состояние* кнопок
   (`dwButtonState`), а не «событие нажатия». Поэтому программа помнит состояние в
   прошлой записи (`prevButtons`) и считает щелчком только момент, когда бит левой
   кнопки *появился* (`pressed = now & ~prev`). Иначе отпускание кнопки и движение
   мыши с удерживаемой кнопкой обрабатывались бы как новые щелчки.
3. **Чтение с экрана.** По координатам щелчка (`dwMousePosition`) вызывается
   `ReadConsoleOutputCharacterW`: система возвращает код символа, который
   *в данный момент* находится в этой ячейке экрана. Если там пробел (или ячейка пуста) —
   вывода нет. Код 1054 в 5.1 — это Unicode-код буквы «О».
4. **Режим консоли.** Кроме `ENABLE_MOUSE_INPUT` программа снимает флаг
   `ENABLE_QUICK_EDIT_MODE` (для этого нужен `ENABLE_EXTENDED_FLAGS`). Если «быстрое
   выделение» включено, консоль забирает щелчки себе для выделения текста, и до
   программы они не доходят. Прежний режим сохраняется и восстанавливается при
   выходе, чтобы не нарушить работу других программ в этом окне.
5. **Усложнённый вариант.** Символ и его цвет меняются прямо в ячейке:
   `FillConsoleOutputAttribute` устанавливает яркий цвет, `WriteConsoleOutputCharacterW`
   записывает на то же место символ другого регистра. Регистр меняют `CharUpperW` /
   `CharLowerW`: они работают с символами Unicode и знают и латиницу, и кириллицу
   (функции `toupper`/`tolower` рассчитаны на однобайтные символы и текущую локаль). Цифры и знаки не имеют регистра, поэтому
   они только перекрашиваются («2» в 5.2). Так как чтение идёт с экрана, второй щелчок
   по той же букве видит уже изменённый регистр и возвращает исходный.
6. **Завершение.** Правая кнопка (`RIGHTMOST_BUTTON_PRESSED`) выводит из цикла;
   программа восстанавливает режим консоли и переводит курсор под рабочую область.

## 7. Ответы на контрольные вопросы

**1. Чем событийное программирование отличается от жёстко алгоритмического,
опишите сферу применений того и другого?**
В алгоритмической программе порядок действий заранее строго описан, и сама программа
решает, что на очередном шаге будет требовать и ожидать (данные с клавиатуры, мыши и т. д.).
В событийной программе порядок действий задаёт внешний мир: она в цикле ждёт
сообщения (нажатие клавиши, движение мыши, изменение размера окна, таймер) и реагирует на
пришедшее; заранее неизвестно, какое событие придёт следующим. Алгоритмический стиль
применяют для вычислений, пакетной обработки данных, утилит-фильтров, консольных
программ с фиксированным диалогом. Событийный — для интерактивных программ с
графическим интерфейсом, игр, обработки действий мыши, программ, обслуживающих
несколько источников данных.

**2. Чем отличается программная обработка нажатий на управляющую клавишу от
аналогичной обработки нажатий на алфавитно-цифровую клавишу при использовании функции
ReadConsoleInput в Windows?**
Нажатие клавиши приходит как `KEY_EVENT` с записью `KEY_EVENT_RECORD`. Для
алфавитно-цифровой клавиши в поле `uChar` находится код введённого символа, и его
обычно достаточно. Для управляющих клавиш (стрелки, F1–F12, Home, End, Shift, Ctrl и др.)
символа нет (в `uChar` ноль), поэтому их распознают по коду клавиши `wVirtualKeyCode`
и состоянию управляющих клавиш `dwControlKeyState` (Shift, Ctrl, Alt и т. п.).
Кроме того, для каждого нажатия и отпускания формируется отдельное сообщение
(`bKeyDown`), и это надо учитывать при обработке.

**3. Почему в современных ОС для получения информации от мыши в прикладных
программах используется событийно организованное программирование, а для получения
информации от клавиатуры — не всегда?**
Данные мыши — это не поток символов, а действия (перемещения, нажатия и отпускания кнопок),
которые происходят в произвольные моменты, и программа не может заранее знать, что
произойдёт и когда; единственный естественный способ — получать сообщения о событиях.
Клавиатурный ввод во многих программах удобно представлять как последовательность
символов, которую программа запрашивает сама в известный ей момент диалога (`getchar`,
`read`, `ReadFile`), то есть в алгоритмическом стиле. В интерактивных графических
программах клавиатура, как и мышь, тоже обрабатывается как источник событий.
