## 1. Цель работы

Сформировать умение использовать память, явно заказываемую в программе: динамическое
выделение памяти и разделяемая между процессами память.

## 2. Краткие теоретические сведения

**Явное получение памяти.** В Unix блок памяти запрашивают функцией
`malloc(size)`, которая возвращает указатель на начало блока (или `NULL`), освобождают
`free`. Адрес можно вывести форматом `%p`. В Windows основная универсальная функция —
`VirtualAlloc(адрес, размер, тип, защита)` (пособие, п. 10.3). Получение памяти двухэтапно:
сначала *резервирование* (`MEM_RESERVE`) — выделение диапазона виртуальных адресов с
построением таблиц страниц, затем *введение в действие* (`MEM_COMMIT`) — выделение самой
памяти. Оба этапа можно объединить: `MEM_RESERVE | MEM_COMMIT`. Защита — `PAGE_READONLY`,
`PAGE_READWRITE` и др. Память выделяется *целыми страницами* (4096 байтов), а адрес
резервирования выравнивается по 64 Кбайт. `VirtualQuery` сообщает о состоянии участка
(`MEM_COMMIT`, `MEM_RESERVE`, `MEM_FREE`, размер региона, права), `VirtualFree` освобождает.

**Разделяемая память.** Процессы изолированы: у каждого своё виртуальное адресное
пространство, и общие данные просто через переменные передать нельзя. Файлы для этого
медленны (на много порядков медленнее оперативной памяти), поэтому ОС предоставляют
*разделяемую память*: область, одновременно отображённую в адресные пространства
нескольких процессов (п. 10.4). Доступ двухэтапный.

* Linux (System V): `shmget(ключ, размер, IPC_CREAT | права)` — получить идентификатор
  области (или создать), `shmat(id, NULL, 0)` — подключить область и получить указатель,
  `shmdt` — отключить, `shmctl(id, IPC_RMID, NULL)` — удалить. Ключ — число, по смыслу
  имя объекта; список объектов — команда `ipcs -m`.
* Windows: `CreateFileMapping((HANDLE)-1, NULL, PAGE_READWRITE, 0, размер, "имя")` —
  создать именованный объект отображения (вместо хэндла файла — `-1`),
  `MapViewOfFile` — получить указатель; второй процесс вызывает `OpenFileMapping` с тем
  же именем; освобождают `UnmapViewOfFile` и `CloseHandle`.

**Оповещение через семафор.** Для сообщения о том, что данные записаны, процессы
используют семафор с начальным значением 0: первый процесс после записи увеличивает его
(`ReleaseSemaphore` в Windows, `semop(+1)` в Linux), второй ждёт (`WaitForSingleObject`,
`semop(-1)`) и после срабатывания читает данные.

## 3. Формулировка задания

**Базовый вариант (Windows).** Две программы для двух процессов с общей памятью. В
первой создаются разделяемая память и семафор. Во второй открывается доступ к ним. Первая
после задержки 10–15 с записывает текст в разделяемую память и указывает его готовность
семафором. Вторая вначале читает данные из того места, где текст должен появиться, и
выводит их с примечанием, затем ждёт семафор и только после этого снова выводит содержимое
разделяемой памяти с примечанием. Обе программы выводят адрес области. Первая программа,
кроме того, после формирования данных запрашивает 1000 байтов через `VirtualAlloc` и
записывает в них латинские буквы через 399 свободных байтов (`a` со смещением 0, `b` —
400, `c` — 800 и т. д., не менее 15 раз), сопровождая каждую запись сообщением и
адресом. Результаты объяснить.

**Усложнённый вариант (Linux).** Первая часть задания — два процесса с разделяемой
памятью — для Linux.

*Трактовки.* (1) Для оповещения используется семафор (в Windows `CreateSemaphore`,
в Linux — семафор System V). (2) Требование «не менее 15 записей» невыполнимо при заказе
1000 байтов (см. объяснение 6.3): программа пишет «сколько возможно», проверяя доступность
страницы функцией `VirtualQuery`, и прекращает запись на первой недоступной.
(3) Параметр `crash` — дополнительный: он показывает, что произошло бы без проверки.

### 4.1. Windows, программа 1 (`lab09/lab9_a.c`)

```c
/*
 * ЛР №9, базовый вариант (Windows), программа 1.
 *
 *  1. Создаёт разделяемую память (CreateFileMapping + MapViewOfFile) и семафор,
 *     выводит адрес области.
 *  2. Ждёт 12 секунд (по заданию 10–15), записывает текст в разделяемую память и
 *     сообщает о его готовности, увеличив семафор (ReleaseSemaphore).
 *  3. Запрашивает 1000 байтов через VirtualAlloc и записывает в них буквы латинского
 *     алфавита через каждые 400 байтов (a — со смещением 0, b — 400, c — 800, ...),
 *     сообщая о каждой записи и её адресе. Перед записью проверяет через
 *     VirtualQuery, что страница доступна для записи, — иначе писать нельзя.
 *     С параметром "crash" запись после этого повторяется без проверки.
 *
 * Запускать ПЕРВОЙ, затем lab9_b.exe.
 * Сборка:  gcc lab9_a.c -o lab9_a.exe -Wall
 */
#include <windows.h>
#include <stdarg.h>
#include <stdio.h>
#include <string.h>

#define SHM_NAME  "OSLAB9_SHM"      /* имя разделяемой памяти (общее для двух программ) */
#define SEM_NAME  "OSLAB9_SEM"      /* имя семафора */
#define SHM_SIZE  4096              /* размер разделяемой области, байтов */
#define DELAY_SEC 12                /* пауза перед записью текста */
#define KEEP_SEC  15                /* сколько держим объекты, пока вторая программа читает */

static void say(const char *fmt, ...)
{
    char text[400];
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(text, sizeof(text), fmt, ap);
    va_end(ap);
    SYSTEMTIME t;
    GetLocalTime(&t);
    printf("[%02d:%02d:%02d] %s\n", t.wHour, t.wMinute, t.wSecond, text);
    fflush(stdout);
}

/* Текстовое описание состояния страницы по результату VirtualQuery. */
static const char *state_name(DWORD s)
{
    return s == MEM_COMMIT ? "MEM_COMMIT (задействована)"
         : s == MEM_RESERVE ? "MEM_RESERVE (только зарезервирована)"
         : "MEM_FREE (свободна)";
}

int main(int argc, char **argv)
{
    SetConsoleOutputCP(CP_UTF8);
    say("Программа 1: создаю разделяемую память и семафор.");

    /* Первый аргумент (HANDLE)-1 вместо хэндла файла означает «память, не файл». */
    HANDLE hMap = CreateFileMapping(INVALID_HANDLE_VALUE, NULL, PAGE_READWRITE,
                                    0, SHM_SIZE, SHM_NAME);
    if (!hMap) { say("CreateFileMapping: ошибка %lu", GetLastError()); return 1; }

    /* Отображаем объект в адресное пространство процесса, получаем указатель. */
    char *pm = MapViewOfFile(hMap, FILE_MAP_WRITE, 0, 0, 0);
    if (!pm) { say("MapViewOfFile: ошибка %lu", GetLastError()); return 1; }
    say("Разделяемая память отображена в моё адресное пространство по адресу %p.", (void *)pm);

    /* Семафор с начальным значением 0 («данных ещё нет») и максимумом 1. */
    HANDLE hSem = CreateSemaphore(NULL, 0, 1, SEM_NAME);
    if (!hSem) { say("CreateSemaphore: ошибка %lu", GetLastError()); return 1; }

    memset(pm, 0, SHM_SIZE);
    strcpy(pm, "(данных пока нет)");
    say("Записал в память заглушку \"%s\". Жду %d с перед записью текста...", pm, DELAY_SEC);
    Sleep(DELAY_SEC * 1000);

    strcpy(pm, "Привет из первой программы! Это текст из разделяемой памяти.");
    say("Записал текст в разделяемую память: \"%s\"", pm);
    ReleaseSemaphore(hSem, 1, NULL);     /* значение семафора 0 -> 1: сообщаем о готовности */
    say("Увеличил семафор: сообщил второй программе, что текст готов.");

    /* ---- Часть 2: память через VirtualAlloc ---- */
    say("Запрашиваю 1000 байтов через VirtualAlloc.");
    char *p = VirtualAlloc(NULL, 1000, MEM_RESERVE | MEM_COMMIT, PAGE_READWRITE);
    if (!p) { say("VirtualAlloc: ошибка %lu", GetLastError()); return 1; }
    say("VirtualAlloc вернула адрес %p.", (void *)p);

    MEMORY_BASIC_INFORMATION mbi;
    VirtualQuery(p, &mbi, sizeof(mbi));
    say("VirtualQuery: размер задействованного участка (RegionSize) = %lu байтов.",
        (unsigned long)mbi.RegionSize);

    int written = 0;
    for (int i = 0; i < 26; i++) {
        char *addr = p + 400 * i;                       /* смещение 0, 400, 800, ... */
        VirtualQuery(addr, &mbi, sizeof(mbi));
        BOOL writable = mbi.State == MEM_COMMIT &&
                        (mbi.Protect & (PAGE_READWRITE | PAGE_EXECUTE_READWRITE));
        if (!writable) {
            say("Смещение %d, адрес %p: запись невозможна — страница в состоянии %s.",
                400 * i, (void *)addr, state_name(mbi.State));
            break;
        }
        *addr = (char)('a' + i);
        written++;
        say("Записал '%c' по смещению %d, адрес %p.", 'a' + i, 400 * i, (void *)addr);
    }
    say("Всего выполнено записей: %d.", written);

    if (argc > 1 && !strcmp(argv[1], "crash")) {
        say("Параметр crash: пишу по смещению 4400 без проверки...");
        *(p + 4400) = 'x';               /* здесь процесс аварийно завершится */
        say("Эта строка не выводится.");
    }

    say("Жду %d с, пока вторая программа читает память.", KEEP_SEC);
    Sleep(KEEP_SEC * 1000);

    VirtualFree(p, 0, MEM_RELEASE);
    UnmapViewOfFile(pm);
    CloseHandle(hSem);
    CloseHandle(hMap);
    say("Программа 1: конец работы.");
    return 0;
}
```

/*
 * ЛР №9, базовый вариант (Windows), программа 2.
 *
 *  1. Открывает уже существующую разделяемую память и семафор, созданные программой 1,
 *     выводит адрес, по которому память отображена в ЭТОМ процессе.
 *  2. Сразу читает текст из разделяемой памяти и выводит его (с примечанием).
 *  3. Ждёт семафор (WaitForSingleObject) — сигнал о готовности текста.
 *  4. После сигнала снова читает память и выводит содержимое (с примечанием).
 *
 * Запускать ПОСЛЕ lab9_a.exe.
 * Сборка:  gcc lab9_b.c -o lab9_b.exe -Wall
 */
#include <windows.h>
#include <stdarg.h>
#include <stdio.h>

#define SHM_NAME "OSLAB9_SHM"
#define SEM_NAME "OSLAB9_SEM"
#define SHM_SIZE 4096

static void say(const char *fmt, ...)
{
    char text[400];
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(text, sizeof(text), fmt, ap);
    va_end(ap);
    SYSTEMTIME t;
    GetLocalTime(&t);
    printf("[%02d:%02d:%02d] %s\n", t.wHour, t.wMinute, t.wSecond, text);
    fflush(stdout);
}

int main(void)
{
    SetConsoleOutputCP(CP_UTF8);
    say("Программа 2: открываю разделяемую память и семафор.");

    /* Открываем существующие объекты по именам (создаёт их программа 1). */
    HANDLE hMap = OpenFileMapping(FILE_MAP_READ, FALSE, SHM_NAME);
    if (!hMap) {
        say("Не удалось открыть разделяемую память (ошибка %lu). Сначала запустите lab9_a.exe.",
            GetLastError());
        return 1;
    }
    const char *pb = MapViewOfFile(hMap, FILE_MAP_READ, 0, 0, SHM_SIZE);
    if (!pb) { say("MapViewOfFile: ошибка %lu", GetLastError()); return 1; }
    say("Разделяемая память отображена в моё адресное пространство по адресу %p.", (const void *)pb);

    /* SYNCHRONIZE — право ждать семафор. */
    HANDLE hSem = OpenSemaphore(SYNCHRONIZE, FALSE, SEM_NAME);
    if (!hSem) { say("OpenSemaphore: ошибка %lu", GetLastError()); return 1; }

    /* Чтение ДО сигнала семафора: там пока только заглушка первой программы. */
    say("Читаю разделяемую память до сигнала семафора: \"%s\"", pb);

    say("Жду сигнала семафора...");
    WaitForSingleObject(hSem, INFINITE);       /* блокируемся, пока значение семафора 0 */
    say("Семафор сработал.");

    say("Читаю разделяемую память после сигнала: \"%s\"", pb);

    UnmapViewOfFile(pb);
    CloseHandle(hSem);
    CloseHandle(hMap);
    say("Программа 2: конец работы.");
    return 0;
}

### 4.3. Linux, программа 1 (`lab09/linux/lab9_a.c`)

```c
/*
 * ЛР №9, усложнённый вариант (Linux), программа 1: создаёт разделяемую память
 * и семафор (System V IPC), через 12 секунд записывает в память текст и
 * сообщает о готовности, увеличив семафор.
 *
 *   shmget + shmat  — получить область разделяемой памяти и её адрес;
 *   semget + semctl — создать семафор и задать ему начальное значение 0;
 *   semop(+1)       — «V»: сообщить второй программе, что текст готов.
 *
 * Запускать ПЕРВОЙ, затем lab9_b.out (из той же папки).
 * Сборка:  gcc lab9_a.c -o lab9_a.out -Wall
 */
#include <stdarg.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include <time.h>
#include <unistd.h>

#define KEY_SHM   0x4C390001     /* числовые «имена» объектов, общие для двух программ */
#define KEY_SEM   0x4C390002
#define SHM_SIZE  4096
#define DELAY_SEC 12             /* пауза перед записью текста */
#define KEEP_SEC  15             /* сколько держим объекты, пока вторая программа читает */

/* Для semctl(SETVAL) в Linux нужно самому описать это объединение. */
union semun { int val; };

static void say(const char *fmt, ...)
{
    char text[400];
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(text, sizeof(text), fmt, ap);
    va_end(ap);
    time_t now = time(NULL);
    struct tm tm;
    localtime_r(&now, &tm);
    printf("[%02d:%02d:%02d] %s\n", tm.tm_hour, tm.tm_min, tm.tm_sec, text);
    fflush(stdout);
}

int main(void)
{
    say("Программа 1: создаю разделяемую память и семафор.");

    /* Область разделяемой памяти: IPC_CREAT — создать, 0600 — права. */
    int shmid = shmget(KEY_SHM, SHM_SIZE, IPC_CREAT | 0600);
    if (shmid == -1) { perror("shmget"); return 1; }

    /* Подключаем область к адресному пространству процесса (NULL — адрес выбирает ОС). */
    char *pm = shmat(shmid, NULL, 0);
    if (pm == (char *)-1) { perror("shmat"); return 1; }
    say("Разделяемая память (shmid %d) отображена в моё адресное пространство по адресу %p.",
        shmid, (void *)pm);

    /* Набор из одного семафора, начальное значение 0 («данных ещё нет»). */
    int semid = semget(KEY_SEM, 1, IPC_CREAT | 0600);
    if (semid == -1) { perror("semget"); return 1; }
    union semun arg = { .val = 0 };
    semctl(semid, 0, SETVAL, arg);

    memset(pm, 0, SHM_SIZE);
    strcpy(pm, "(данных пока нет)");
    say("Записал в память заглушку \"%s\". Жду %d с перед записью текста...", pm, DELAY_SEC);
    sleep(DELAY_SEC);

    strcpy(pm, "Привет из первой программы! Это текст из разделяемой памяти.");
    say("Записал текст в разделяемую память: \"%s\"", pm);

    struct sembuf up = { .sem_num = 0, .sem_op = +1, .sem_flg = 0 };   /* V: значение 0 -> 1 */
    semop(semid, &up, 1);
    say("Увеличил семафор: сообщил второй программе, что текст готов.");

    say("Жду %d с, пока вторая программа читает память.", KEEP_SEC);
    sleep(KEEP_SEC);

    shmdt(pm);                          /* отключить память от процесса */
    shmctl(shmid, IPC_RMID, NULL);      /* удалить область (сама она не исчезает!) */
    semctl(semid, 0, IPC_RMID);         /* удалить семафор */
    say("Программа 1: объекты удалены, конец работы.");
    return 0;
}
```

### 4.4. Linux, программа 2 (`lab09/linux/lab9_b.c`)

```c
/*
 * ЛР №9, усложнённый вариант (Linux), программа 2: открывает разделяемую память и
 * семафор, созданные программой 1.
 *
 *  1. shmget без IPC_CREAT + shmat — подключается к существующей области, выводит
 *     адрес, по которому она отображена в ЭТОМ процессе.
 *  2. Сразу читает текст и выводит его (с примечанием).
 *  3. Ждёт семафор (semop с операцией -1 блокирует, пока значение равно 0).
 *  4. После сигнала снова читает память и выводит содержимое.
 *
 * Запускать ПОСЛЕ lab9_a.out.
 * Сборка:  gcc lab9_b.c -o lab9_b.out -Wall
 */
#include <stdarg.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include <time.h>
#include <unistd.h>

#define KEY_SHM  0x4C390001
#define KEY_SEM  0x4C390002
#define SHM_SIZE 4096

static void say(const char *fmt, ...)
{
    char text[400];
    va_list ap;
    va_start(ap, fmt);
    vsnprintf(text, sizeof(text), fmt, ap);
    va_end(ap);
    time_t now = time(NULL);
    struct tm tm;
    localtime_r(&now, &tm);
    printf("[%02d:%02d:%02d] %s\n", tm.tm_hour, tm.tm_min, tm.tm_sec, text);
    fflush(stdout);
}

int main(void)
{
    say("Программа 2: открываю разделяемую память и семафор.");

    /* Область уже существует — флаг IPC_CREAT не нужен. */
    int shmid = shmget(KEY_SHM, SHM_SIZE, 0600);
    if (shmid == -1) {
        perror("shmget (сначала запустите lab9_a.out)");
        return 1;
    }
    /* SHM_RDONLY — только чтение: эта программа память не меняет. */
    const char *pb = shmat(shmid, NULL, SHM_RDONLY);
    if (pb == (const char *)-1) { perror("shmat"); return 1; }
    say("Разделяемая память (shmid %d) отображена в моё адресное пространство по адресу %p.",
        shmid, (const void *)pb);

    int semid = semget(KEY_SEM, 1, 0600);
    if (semid == -1) { perror("semget"); return 1; }

    say("Читаю разделяемую память до сигнала семафора: \"%s\"", pb);

    say("Жду сигнала семафора...");
    struct sembuf down = { .sem_num = 0, .sem_op = -1, .sem_flg = 0 };   /* P: ждать и захватить */
    semop(semid, &down, 1);                                             /* блокируется, пока 0 */
    say("Семафор сработал.");

    say("Читаю разделяемую память после сигнала: \"%s\"", pb);

    shmdt(pb);
    say("Программа 2: конец работы.");
    return 0;
}
```

Сборка (предупреждений нет): `gcc имя.c -o имя.exe -Wall -Wextra` (Windows) и
`gcc имя.c -o имя.out -Wall -Wextra` (Linux).

## 6. Объяснение результатов

1. **Общие данные.** Программа 2 до сигнала семафора прочитала заглушку «(данных пока
   нет)», которую первая программа записала при создании области. Затем она блокируется на
   семафоре (значение 0). После записи текста первая программа увеличивает семафор, вторая
   «просыпается» (в 23:58:20 — в тот же момент, что и запись) и читает новый текст. Обе
   программы работают с одной и той же физической памятью: изменение, сделанное в одном
   процессе, видно в другом.
2. **Адреса разные.** Первая программа видит область по адресу `…282513E0000`, вторая —
   `…1395A9F0000` (в Linux — `0x7f328f23f000` и `0x7b295ecca000`). Адреса — виртуальные и
   относятся к адресному пространству каждого процесса; ОС отображает одну и ту же
   область памяти в разные места. Поэтому нельзя хранить внутри разделяемой памяти
   указатели на данные в ней.
3. **`VirtualAlloc` на 1000 байтов.** Запрос дал адрес `…513F0000`, а `VirtualQuery`
   показала размер `RegionSize = 4096`: память выделяется *целыми страницами*, задействована
   вся страница, хотя заказано 1000 байтов. Поэтому записи по смещениям 0, 400, …, 4000
   (11 штук: `a`…`k`) прошли успешно, хотя смещения 1200, 1600 и т. д. лежат за пределами
   «заказанных» 1000 байтов. Адреса записей идут с шагом 400 = `0x190` (…0000, …0190,
   …0320, …). Смещение 4400 уже находится на следующей странице, которая не выделена
   (состояние `MEM_FREE`), и запись в неё невозможна. Поэтому «не менее 15 записей»
   выполнить нельзя: для 15 записей нужно ≥ 5601 байт (две страницы).
4. **Аварийное завершение.** Запись по недоступной странице без проверки приводит к
   исключению *нарушения доступа*; процесс аварийно завершается с кодом `0xC0000005`
   (`EXCEPTION_ACCESS_VIOLATION`), как показал запуск с параметром `crash`. Проверка через
   `VirtualQuery` позволяет узнать о недоступности заранее.
5. **Linux.** `shmget` создаёт объект в ядре (виден в `ipcs -m`: ключ `0x4c390001`,
   4096 байтов, `nattch = 1` — подключена одна программа, права 600); `shmat` подключает
   его к процессу. В отличие от Windows, объект не исчезает сам, поэтому первая программа
   в конце удаляет его (`shmctl(IPC_RMID)`), после чего `ipcs -m` пуст.
6. **Освобождение.** В Windows объекты разделяемой памяти и семафора существуют, пока
   открыт хотя бы один хэндл; поэтому первая программа держит их 15 с после записи, пока
   вторая читает.

## 7. Ответы на контрольные вопросы

**1. Чем абстрактные семафоры отличаются от известных вам программных реализаций.**
Абстрактный семафор — идеальная переменная с атомарными операциями P и V (двоичный: 0
и 1, считающий — неотрицательные значения). В ОС это конкретные объекты с дополнительными
свойствами: в Windows — `CreateSemaphore` (начальное значение, верхняя граница, имя для
использования несколькими процессами, ожидание функцией `WaitForSingleObject` с
тайм-аутом, увеличение — `ReleaseSemaphore`), в Linux — семафоры System V (`semget`,
`semop` — наборы семафоров, изменение на произвольное число) и POSIX (`sem_wait`,
`sem_post`). Реализации позволяют именованный общий доступ процессов и ожидание с
ограничением времени, чего нет в абстрактной схеме.

**2. Какие программные средства для решения проблемы тупиков при взаимодействии
программных единиц в Windows вы знаете?**
Тупик (deadlock) — взаимное бесконечное ожидание: например, процесс A захватил S1 и
ждёт S2, а процесс B захватил S2 и ждёт S1. Средства Windows: (1) ожидание с ограничением
времени — параметр `Timeout` функции `WaitForSingleObject`: по истечении времени функция
возвращает `WAIT_TIMEOUT`, и программа может освободить захваченное и повторить
попытку; (2) множественное ожидание `WaitForMultipleObjects` с `fWaitAll = TRUE`: нить
ожидает сразу весь набор объектов и получает их только вместе, поэтому не держит один объект,
ожидая другой; (3) организационная мера — единый порядок захвата объектов во всех
программах и использование мьютексов с владельцем.

**3. Укажите в каких ситуациях предпочтительней использование мьютексов вместо
семафоров и в каких ситуациях целесообразно обратное предпочтение.**
Мьютекс — для взаимного исключения в критическом интервале, где захватывает и освобождает
одна и та же нить (защита общего ресурса, вывод на экран); владение защищает от
освобождения «чужой» нитью. Семафор — когда нужен подсчёт ресурсов или сигнализация между
разными нитями и процессами: захватывает одна, освобождает другая (как в этой работе — первая
программа увеличивает семафор, а вторая ждёт его; мьютекс для такой передачи сигнала не
подходит, так как освободить его мог бы только владелец).

**4. Объясните, с чем связано большая сложность использования функций явного
распределения памяти в Windows по сравнению с аналогичными функциями в Unix.**
В Unix есть простая функция `malloc(size)` — один аргумент, возвращающая указатель. В
Windows `VirtualAlloc` имеет четыре аргумента: адрес, размер, тип и защиту. Сложность
отражает устройство виртуальной памяти процессоров Intel: страничная адресация
двухуровневая, и память выделяется в два этапа — резервирование адресов
(построение таблиц страниц) и введение в использование (выделение самой памяти), причём
их нужно правильно комбинировать; кроме того, задаются права доступа к страницам,
учитываются размер страницы (4096) и выравнивание по 64 Кбайт. Всё это разработчики
Windows сделали видимым программисту ради эффективности, а `malloc` скрывает такие
подробности внутри библиотеки.
