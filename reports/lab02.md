## 1. Цель работы

Изучить связь файлов, их хэндлов и управляющих блоков файлов.

## 2. Краткие теоретические сведения

**Управляющий блок файла.** Пока файл просто лежит на диске, никакой учётной
информации о его использовании не нужно. Когда программа открывает файл,
операционная система создаёт для него *управляющий блок* (file control block).
Главное, что в нём хранится, — *текущая позиция* ввода-вывода (смещение, offset),
с которой будет выполнена следующая операция чтения или записи, а также вид
доступа, заданный при открытии (чтение, запись или то и другое), и сведения о
размещении файла. Функции позиционирования (`lseek`, `SetFilePointer`) меняют
не файл, а именно эту позицию в управляющем блоке (учебное пособие, п. 2.1).

**Хэндл (дескриптор).** Управляющие блоки лежат в служебной области ОС,
недоступной программе, в таблице (своей для каждого процесса). Хэндл — это номер
строки этой таблицы. Через него программа и обращается к управляющему блоку.

**Открытие и закрытие.** В Linux файл открывает `open(имя, режим, права)`,
возвращающая хэндл или `-1`; в Windows — `CreateFile`, которая возвращает хэндл
или `INVALID_HANDLE_VALUE`. Закрытие (`close` / `CloseHandle`) уничтожает
управляющий блок (если на него не ссылаются другие хэндлы).

**Дублирование хэндла.** К одному и тому же управляющему блоку можно получить
ещё один хэндл: в Linux — `dup(fd)` (даётся наименьший свободный номер), в
Windows — `DuplicateHandle`. Оба хэндла указывают на *один* блок, поэтому у них
*общая* текущая позиция: чтение через один сдвигает позицию и для другого. Повторное
`open`/`CreateFile` того же файла, наоборот, создаёт *новый* блок со своей
собственной позицией, начинающейся с нуля.

**Позиционирование.** `lseek(fd, смещение, откуда)` в Linux и
`SetFilePointer(h, смещение, NULL, откуда)` в Windows; точка отсчёта —
`SEEK_SET`/`FILE_BEGIN` (от начала), `SEEK_CUR`/`FILE_CURRENT` (от текущей
позиции), `SEEK_END`/`FILE_END` (от конца).

### 4.1. Linux, программа 1 — создание файла (`lab02/lab2_create.c`)

```c
/*
 * ЛР №2, программа 1 (Linux): создаёт текстовый файл data.txt из данных,
 * введённых со стандартного ввода.
 *
 * Сборка:  gcc lab2_create.c -o lab2_create.out -Wall
 * Запуск:  ./lab2_create.out <input.txt      (или набрать строку с клавиатуры)
 */
#include <fcntl.h>   /* open, O_* */
#include <stdio.h>   /* perror */
#include <unistd.h>  /* read, write, close */

#define FNAME "data.txt"

int main(void)
{
    char buf[256];

    /* Открываем файл для записи: O_CREAT — создать, если нет;
     * O_TRUNC — обнулить, если уже был. 0600 — права rw для владельца.
     * open возвращает файловый дескриптор (хэндл) или -1 при ошибке. */
    int fd = open(FNAME, O_WRONLY | O_CREAT | O_TRUNC, 0600);
    if (fd == -1) {
        perror("open");
        return 1;
    }

    /* Читаем текст из стандартного ввода (дескриптор 0).
     * С клавиатуры вернётся одна строка, из файла — до sizeof(buf) байт. */
    ssize_t n = read(STDIN_FILENO, buf, sizeof(buf));
    if (n < 0) {
        perror("read");
        close(fd);
        return 1;
    }

    /* Пишем ровно столько байтов, сколько прочитали, в файл. */
    if (write(fd, buf, (size_t)n) != n) {
        perror("write");
        close(fd);
        return 1;
    }

    close(fd);   /* закрытие файла: ОС освобождает его управляющий блок */
    return 0;
}
```

### 4.2. Linux, программа 2 — три хэндла (`lab02/lab2_read.c`)

```c
/*
 * ЛР №2, программа 2 (Linux), базовый вариант: три хэндла одного файла.
 *
 *   fd1 = open(...)          — первое открытие файла;
 *   fd2 = dup(fd1)           — второй номер для ТОГО ЖЕ управляющего блока;
 *   fd3 = open(...)          — повторное открытие: НОВЫЙ управляющий блок.
 *
 * Затем позиция устанавливается через fd1 на 10-й байт, выводятся числовые
 * значения хэндлов, и из файла по очереди через fd1, fd2, fd3 читается
 * по 7 символов, каждый кусок выводится на экран в своей строке.
 *
 * Сборка:  gcc lab2_read.c -o lab2_read.out -Wall
 * Запуск:  ./lab2_read.out        (файл data.txt создаёт lab2_create)
 */
#include <fcntl.h>   /* open */
#include <stdio.h>   /* perror, dprintf */
#include <unistd.h>  /* read, close, dup, lseek */

#define FNAME "data.txt"
#define PORTION 7        /* сколько символов читаем за раз */
#define START   10       /* позиция для lseek */

/* Читает PORTION байтов через хэндл fd и выводит их в отдельной строке. */
static void read_and_print(const char *name, int fd)
{
    char buf[PORTION + 1];
    ssize_t n = read(fd, buf, PORTION);   /* позиция берётся из управляющего блока */
    if (n < 0) {
        perror("read");
        return;
    }
    buf[n] = '\0';
    /* dprintf пишет сразу в дескриптор 1 без буфера stdio */
    dprintf(STDOUT_FILENO, "%s: %s\n", name, buf);
}

int main(void)
{
    /* 1-й хэндл: обычное открытие для чтения. */
    int fd1 = open(FNAME, O_RDONLY);
    if (fd1 == -1) {
        perror("open #1");
        return 1;
    }

    /* 2-й хэндл: dup даёт новый (минимальный свободный) номер, но он указывает
     * на тот же управляющий блок, а значит, и на ту же текущую позицию. */
    int fd2 = dup(fd1);
    if (fd2 == -1) {
        perror("dup");
        return 1;
    }

    /* 3-й хэндл: второе открытие того же файла создаёт отдельный управляющий
     * блок со своей собственной позицией (она начинается с 0). */
    int fd3 = open(FNAME, O_RDONLY);
    if (fd3 == -1) {
        perror("open #3");
        return 1;
    }

    /* Позиционируем чтение через ПЕРВЫЙ хэндл: 10-я позиция от начала файла. */
    if (lseek(fd1, START, SEEK_SET) == -1) {
        perror("lseek");
        return 1;
    }

    dprintf(STDOUT_FILENO, "Значения хэндлов: fd1 = %d, fd2 = %d, fd3 = %d\n",
            fd1, fd2, fd3);

    /* По очереди используем все три хэндла. */
    read_and_print("fd1", fd1);
    read_and_print("fd2", fd2);
    read_and_print("fd3", fd3);

    /* Для объяснения результатов: текущие позиции в управляющих блоках.
     * lseek(fd, 0, SEEK_CUR) позицию не меняет, а только сообщает её. */
    dprintf(STDOUT_FILENO, "Текущие позиции: fd1 = %ld, fd2 = %ld, fd3 = %ld\n",
            (long)lseek(fd1, 0, SEEK_CUR),
            (long)lseek(fd2, 0, SEEK_CUR),
            (long)lseek(fd3, 0, SEEK_CUR));

    close(fd1);
    close(fd2);
    close(fd3);
    return 0;
}
```

### 4.3. Windows — усложнённый вариант (`lab02/lab2_win.c`)

```c
/*
 * ЛР №2, усложнённый вариант (Windows): то же задание, что lab2_read.c,
 * но дублирование хэндла выполняется функцией DuplicateHandle (вместо dup).
 *
 *   h1 = CreateFile(...)       — первое открытие файла;
 *   h2 = DuplicateHandle(h1)   — второй хэндл на ТОТ ЖЕ объект «файл»;
 *   h3 = CreateFile(...)       — повторное открытие: новый объект «файл».
 *
 * Позиция устанавливается через h1 на 10-й байт, затем через h1, h2, h3
 * читается по 7 символов; каждый кусок выводится в своей строке.
 *
 * Сборка:  gcc lab2_win.c -o lab2_win.exe -Wall
 * Запуск:  .\lab2_win.exe        (файл data.txt — рядом с программой)
 */
#include <windows.h>
#include <stdarg.h>
#include <stdio.h>

#define FNAME   "data.txt"
#define PORTION 7
#define START   10

static HANDLE hOut;   /* хэндл стандартного вывода */

/* Формирует строку и выводит её в stdout небуферизованным WriteFile. */
static void print(const char *fmt, ...)
{
    char msg[256];
    va_list ap;
    va_start(ap, fmt);
    int len = vsnprintf(msg, sizeof(msg), fmt, ap);
    va_end(ap);
    DWORD written;
    WriteFile(hOut, msg, (DWORD)len, &written, NULL);
}

/* Читает PORTION байтов через хэндл h и выводит их в отдельной строке. */
static void read_and_print(const char *name, HANDLE h)
{
    char buf[PORTION + 1];
    DWORD n = 0;
    if (!ReadFile(h, buf, PORTION, &n, NULL)) {
        print("%s: ошибка ReadFile, код %lu\r\n", name, GetLastError());
        return;
    }
    buf[n] = '\0';
    print("%s: %s\r\n", name, buf);
}

/* Текущая позиция в файле (SetFilePointer с нулевым смещением от FILE_CURRENT). */
static unsigned long pos(HANDLE h)
{
    return SetFilePointer(h, 0, NULL, FILE_CURRENT);
}

int main(void)
{
    SetConsoleOutputCP(CP_UTF8);
    hOut = GetStdHandle(STD_OUTPUT_HANDLE);
    if (hOut == INVALID_HANDLE_VALUE) return 1;

    /* 1-й хэндл. FILE_SHARE_READ позволяет открывать файл повторно. */
    HANDLE h1 = CreateFile(FNAME, GENERIC_READ, FILE_SHARE_READ, NULL,
                           OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);
    if (h1 == INVALID_HANDLE_VALUE) {
        print("Не открыт файл " FNAME ", код %lu\r\n", GetLastError());
        return 1;
    }

    /* 2-й хэндл: копия h1 в пределах текущего процесса. Оба хэндла ссылаются
     * на один и тот же объект ядра «файл», а значит, на одну и ту же позицию. */
    HANDLE h2 = NULL;
    if (!DuplicateHandle(GetCurrentProcess(), h1,   /* откуда: процесс, хэндл */
                         GetCurrentProcess(), &h2,  /* куда: процесс, адрес копии */
                         0, FALSE, DUPLICATE_SAME_ACCESS)) {
        print("DuplicateHandle: код %lu\r\n", GetLastError());
        return 1;
    }

    /* 3-й хэндл: второе открытие того же файла — отдельный объект с позицией 0. */
    HANDLE h3 = CreateFile(FNAME, GENERIC_READ, FILE_SHARE_READ, NULL,
                           OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);
    if (h3 == INVALID_HANDLE_VALUE) {
        print("Не открыт файл повторно, код %lu\r\n", GetLastError());
        return 1;
    }

    /* Позиционирование через ПЕРВЫЙ хэндл: 10 байт от начала файла. */
    if (SetFilePointer(h1, START, NULL, FILE_BEGIN) == INVALID_SET_FILE_POINTER) {
        print("SetFilePointer: код %lu\r\n", GetLastError());
        return 1;
    }

    print("Значения хэндлов: h1 = %p, h2 = %p, h3 = %p\r\n", h1, h2, h3);

    read_and_print("h1", h1);
    read_and_print("h2", h2);
    read_and_print("h3", h3);

    print("Текущие позиции: h1 = %lu, h2 = %lu, h3 = %lu\r\n",
          pos(h1), pos(h2), pos(h3));

    CloseHandle(h1);
    CloseHandle(h2);
    CloseHandle(h3);
    return 0;
}
```

## 6. Объяснение результатов

В обоих случаях результат одинаков (отличаются только числовые значения хэндлов).

1. **`dup` даёт новый номер, но не новый управляющий блок.** Хэндлы `fd1` (3) и
   `fd2` (4) указывают на один и тот же блок. Номера 0, 1, 2 заняты стандартными
   потоками, поэтому первое открытие получило 3, `dup` — наименьший свободный номер
   4, а второе открытие — 5.
2. **Второе `open` создаёт отдельный блок.** `fd3` (5) ссылается на свой
   управляющий блок, где позиция начинается с нуля и о `lseek` через `fd1` ничего
   не известно.
3. **Что прочитано.** `lseek(fd1, 10, ...)` поставил позицию общего блока `fd1`/`fd2`
   на 10-й байт. Чтение через `fd1` взяло 7 байтов с 10-го по 16-й — `ABCDEFG` — и
   сдвинуло общую позицию на 17. Чтение через `fd2` продолжило с неё — `HIJKLMN`
   (байты 17–23) — и сдвинуло позицию на 24. Чтение через `fd3` началось с нуля, так как
   у него свой блок — `0123456`.
4. **Проверка.** Дополнительная строка «Текущие позиции» (вызов `lseek(fd, 0,
   SEEK_CUR)` или `SetFilePointer(h, 0, NULL, FILE_CURRENT)`, позицию они не
   меняют) показывает: у `fd1` и `fd2` позиция одна и та же (24), у `fd3` — своя (7).
   Это прямое подтверждение того, что позиция хранится в управляющем блоке, а не в
   хэндле.
5. **Windows.** `DuplicateHandle` ведёт себя как `dup`: `h1` и `h2` ссылаются на
   один объект «файл». Числовые значения хэндлов в Windows не идут подряд (они
   кратны 4 и выдаются из общей таблицы объектов процесса), но суть та же.

## 7. Ответы на контрольные вопросы

**1. Чем открытый файл в операционной системе отличается от неоткрытого,
обосновать ответ.**
Неоткрытый файл — это только данные на носителе с именем; никакой учётной
информации об их использовании нет. Открытый файл — это файл, для которого ОС
создала управляющий блок (текущая позиция, вид доступа, сведения о размещении) и
выдала программе хэндл для обращения к нему. Без открытия невозможно
последовательное чтение и запись: ОС не знала бы, с какого места продолжать.

**2. Зачем закрывается файл, что происходит, если программист не указал явную
функцию закрытия файла?**
При закрытии ОС уничтожает управляющий блок (если на него не осталось других
хэндлов), освобождает строку таблицы хэндлов процесса (их число ограничено) и снимает
ограничения совместного доступа, установленные процессом. Если закрытие не
выполнено явно, файл остаётся занятым до завершения программы — при её завершении ОС
закрывает оставшиеся хэндлы сама, но в долго работающей программе это приводит
к утечке хэндлов и к тому, что другие процессы не могут получить доступ к файлу.

**3. Что содержится в управляющем блоке файла?**
Минимум — текущая позиция ввода-вывода (номер байта, с которого выполнится
следующая операция) и вид доступа, заданный при открытии. Как правило, также
сведения о размещении файла на носителе (его начало), позволяющие быстро добраться до
данных.

**4. Где относительно остальной части программы находится управляющий блок
файла, используемый в этой программе?**
Вне программы: в служебной области операционной системы, недоступной
прикладной программе (в таблице управляющих блоков процесса). Программа хранит
только хэндл — номер строки этой таблицы. Раннее размещение блока в области
данных самой программы (как FCB в первых версиях MS DOS) оказалось менее надёжным, так как блок
можно было испортить ошибкой в программе.
