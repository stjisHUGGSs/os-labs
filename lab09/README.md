# ЛР №9 — разделяемая память и явное распределение памяти

| Файл | Что это |
|---|---|
| `lab9_a.c`, `lab9_b.c` | Базовый вариант, Windows: две программы с общей памятью и семафором + `VirtualAlloc` |
| `linux/lab9_a.c`, `linux/lab9_b.c` | Усложнённый вариант, Linux: то же взаимодействие через System V (`shmget`/`shmat`, `semget`/`semop`) |

## Базовый вариант (Windows)

Из папки `lab09`. Программы запускаются в двух окнах: сначала первая, затем вторая.

```
gcc lab9_a.c -o lab9_a.exe -Wall
gcc lab9_b.c -o lab9_b.exe -Wall
.\lab9_a.exe
.\lab9_b.exe
```

Первая создаёт память и семафор, через 12 с записывает текст и сигналит семафором, затем
работает с `VirtualAlloc` (буквы через 400 байтов). Вторая читает память до и после
сигнала. Параметр `crash` у первой программы (`.\lab9_a.exe crash`) выполняет в конце
запись за пределы выделенной страницы без проверки — процесс аварийно завершается.

## Усложнённый вариант (Linux)

Из папки `lab09/linux`:

```
gcc lab9_a.c -o lab9_a.out -Wall
gcc lab9_b.c -o lab9_b.out -Wall
./lab9_a.out        # в одной консоли
./lab9_b.out        # в другой
```

Во время работы первой программы объект памяти виден командой `ipcs -m`; по завершении
первая программа его удаляет.

Результаты и ответы на контрольные вопросы — в `reports/lab09.md`.
