# ЛР №1 — стандартный ввод-вывод и его переадресация

| Файл | Что это |
|---|---|
| `lab1.c` | Базовый вариант, Windows (`GetStdHandle`, `ReadFile`, `WriteFile`) |
| `lab1_linux.c` | Усложнённый вариант, Linux (`isatty`, `read`, `write`) |
| `input.txt` | Входные данные для запуска с переадресацией |

Команды ниже выполняются из корня репозитория.

## Базовый вариант (Windows)

Сборка:

```
gcc lab01/lab1.c -o lab01/lab1.exe -Wall
```

Запуск с клавиатуры (ввод и вывод по умолчанию):

```
cd lab01
.\lab1.exe
```

Запуск с переадресацией ввода и вывода. Оператор `<` не работает в PowerShell,
поэтому через `cmd`:

```
cd lab01
cmd /c ".\lab1.exe <input.txt >output.txt"
```

Программа выводит значения хэндлов, приглашение, читает строку и повторяет её
после предуведомления. В базовом варианте всё пишется в `stdout` через
`WriteFile` безусловно, поэтому при `>output.txt` приглашение оказывается в
файле вместе со всем остальным — программа не знает, куда указывает хэндл.

## Усложнённый вариант (Linux)

Сборка:

```
gcc lab01/lab1_linux.c -o lab01/lab1_linux.out -Wall -Wextra
```

| Запуск | Приглашение | Результат |
|---|---|---|
| `./lab01/lab1_linux.out` | на экране | на экране |
| `./lab01/lab1_linux.out <lab01/input.txt` | нет | на экране |
| `./lab01/lab1_linux.out >lab01/out.txt` | на экране | в `out.txt` |
| `./lab01/lab1_linux.out <lab01/input.txt >lab01/out.txt` | нет | в `out.txt` |

Приглашение печатается, только если `isatty(0)` вернул не ноль, и идёт в
`/dev/tty`, а не в дескриптор 1, поэтому при `>out.txt` в файл не попадает.
Подробности — в комментариях в коде и в отчёте (`reports/lab01.md`).
